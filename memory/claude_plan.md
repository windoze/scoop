# 执行计划（单任务迭代）

本文件记录本次调用的执行步骤与进度。遵循：先处理最新提交中提到的遗留问题；再从 `TODO.md` 里找第一个未完成任务，仅完成这一项并停止。

## 计划

1. 查看最新一次 Git 提交信息（`git log -1`）。
   - 如果提交信息提到已知问题/回归/临时 workaround：优先定位并修复该问题；修复后跑相关测试；提交修复。
2. 读取 `TODO.md`，定位第一个未完成任务。
3. 若该任务过大：
   - 在 `PLAN.md` 写出可执行的细分步骤。
   - 在 `TODO.md` 将原任务拆分为多个子任务（保持依赖顺序），本次只执行其中第一个子任务。
   - 提交一次仅包含文档/任务拆分的提交，然后继续执行“本次要做的第一个子任务”。
4. 实现本次要做的任务（或子任务）。
   - 尽量做最小但正确的改动，不引入 workaround。
   - 若发现任何既有 bug/规格不符/实现边界：立即修复；若修复本身需要另立任务，则把它作为前置任务插入 `TODO.md` 并停止。
5. 测试与质量门禁：
   - 运行相关测试（至少 `cargo test --all`；若影响面更大则补充 fixture/spec 检查）。
   - 运行 `cargo clippy --all-targets -- -D warnings`，确保无 warning。
6. 文档与任务状态更新：
   - 在 `TODO.md` 将本次任务标记为完成。
   - 必要时更新 `PLAN.md`（体现当前状态/调整）。
7. Git 提交：
   - 使用仓库惯例的提交信息（如 `[Txxxx] ...`）。
   - 提交后 `git status` 确认工作区干净。
8. 停止，不处理下一个任务。
