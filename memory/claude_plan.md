4. 只执行排在最前面的那个未完成任务或新拆出的首个子任务。

## 初始步骤

1. 检查最近一次提交信息与提交内容，确认是否明确提到遗留问题、回退、临时方案、已知缺陷。
2. 阅读 `TODO.md` 与 `PLAN.md`，确认当前优先级、依赖关系与首个未完成任务。
3. 阅读与该任务直接相关的代码、测试、规格或注释，建立最小充分上下文。
4. 判断是否存在阻塞该任务的既有缺陷、规格不匹配或未完成实现边界。

## 决策规则

- 如果最新提交提到既有问题，优先修复该问题，再继续。
- 如果在探查或测试中发现任何既有缺陷，而且它阻塞当前任务，则必须先修复；若本轮不能直接修复，则先在 `TODO.md` 中把它插入为前置任务，更新 `PLAN.md` 后提交并停止。
- 不接受规避实现缺口的权宜做法；如果规格路径坏了，就修规格对应的实现或把修复任务前置。
- 只完成一个任务；若只是做了任务拆分或依赖重排，也算本轮完成内容，随后停止。
