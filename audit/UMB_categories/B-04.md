- Root cause: 函数签名、参数类型、返回类型和 allocation helper return type 在 MIR materialize 后仍可为空或不一致，LLVM helper 因而承担了签名补全职责。缺失的不变量是每个 lowered callable 的 signature shape 已发布且与 TypeStore 一致。

- `MIR materialize: function signatures, params, and returns are published` (29 entries).

- Dominant kind labels: `function return type` (6), `scoop_alloc_typed return type` (6), `function param type` (4), `DYNAMIC:kind` (2), `scoop_alloc_typed enum box return type` (1).
