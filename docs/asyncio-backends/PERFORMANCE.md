# 后端性能记录

日期：2026-10-27。对应[设计](DESIGN.md)和[正确性验收](PROGRESS.md)。这是同机三轮诊断测量，不是通用性能保证，也不设置程序合法性或测试通过阈值。

## 环境与方法

- Darwin：Apple M4 Pro、64 GiB、macOS 27.0.1；Linux：NUC12、Core i7-12700H、约 62.5 GiB、内核 7.0.0-38，分别使用 glibc 2.43 和 musl 1.2.5。
- 相同 release 编译器、core／std 与[测量 Cone](benchmarks/README.md)。基线取 `eb81be354` 的 libuv 后端及兼容 platform，平台版取本次实现；构造入口分别为 `LibuvEventLoop`／`PlatformEventLoop`。
- 先完成编译，再交错运行两版各三次；表中是三个样本的中位数。没有后台编译，没有 GC stress；原始样本、测试事件与日志保存在仓库外。
- 每次先等待 200 ms，再执行 30 次 1 ms timer；文件以 64 KiB 分块累计读写 16 MiB。写计时不含 buffer 填充，使用刚写入的文件读取，未执行 fsync，反映 warm page cache 路径。`run` 收尾从正文结束计时，此时文件已关闭，但 native worker 仍需退休。

## 同步 run 对照

每格为“libuv → 平台后端”；除切换次数外均保留三位小数。timer 最大值一行是每轮 30 次中的最大值再取三轮中位数。

| 指标 | Darwin | GNU | musl |
| --- | ---: | ---: | ---: |
| 200 ms 等待实际墙钟（ms） | 202.155 → 210.142 | 200.374 → 200.146 | 200.379 → 200.157 |
| 该等待的进程 CPU（µs） | 234.000 → 405.000 | 111.042 → 92.906 | 115.120 → 99.935 |
| 自愿上下文切换次数 | 0 → 0 | 1 → 1 | 1 → 1 |
| 1 ms timer 平均超时（µs） | 320.466 → 575.200 | 114.124 → 30.786 | 109.545 → 38.795 |
| 1 ms timer 最大超时（µs） | 489.000 → 721.000 | 186.266 → 120.832 | 197.332 → 129.274 |
| 16 MiB 文件读取（ms） | 2.983 → 3.364 | 4.469 → 3.786 | 5.232 → 3.390 |
| 16 MiB 文件写入（ms） | 7.490 → 8.250 | 25.396 → 7.401 | 28.222 → 7.126 |
| run 收尾（µs） | 18.000 → 22.000 | 40.046 → 125.389 | 37.788 → 317.626 |

Linux 的读取计时降低约 15%／35%，写入降低约 71%／75%，1 ms timer 的平均超时也降低；两种 libc 的收尾计时增加。Darwin 的文件读取／写入计时分别增加约 13%／10%，timer 与空闲 CPU 也高于基线。本次不据此宣称全面加速，也不把三个短样本外推到冷盘、持久化写入或长时间负载。

`getrusage(RUSAGE_SELF).ru_nvcsw` 是自愿上下文切换计数，不是硬件唤醒计数；Darwin 返回零不能解释为整个等待没有唤醒。以下宿主测试直接统计回调，验证空闲时没有周期性 pump。

## 宿主推进

`EventLoopHostProgressTest` 使用真实 poll fd-watch，三目标各运行三次，指标取中位数。50 ms 空闲窗口的回调增量每次均为零；随后 post 唤醒并关闭 session。连续 I/O 用 64 次 UDP 发送／接收，检查每次完成之间宿主都有机会处理下一轮；最大间隔包括两次 host.step 之间的等待与处理。

| 指标 | Darwin | GNU | musl |
| --- | ---: | ---: | ---: |
| 空闲回调增量 | 0 | 0 | 0 |
| 50 ms 空闲进程 CPU（µs） | 22.000 | 34.811 | 44.650 |
| post 到执行（µs） | 26.000 | 31.346 | 35.245 |
| 请求关闭到 onClosed（µs） | 132.000 | 161.042 | 159.739 |
| 连续 UDP 下最大宿主轮次间隔（µs） | 113.000 | 52.464 | 58.218 |

旧 libuv 入口没有 attach 协议，因此宿主表没有同接口基线。Darwin 的真实 MainDispatchHost／CFRunLoop 已做功能与移动 GC 验证，表中延迟来自 poll 型宿主；AppKit 菜单、拖动、模态以及 Wayland／X11 窗口循环仍属于未来 GUI 层验收。用户回调或不可中断 syscall 可能运行更久，上述数字不构成关闭或 UI 响应时间上限。
