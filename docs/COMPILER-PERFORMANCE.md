# 编译性能修复验收

本轮以实际编译、产物消费和运行结果验证性能修复。性能数字是本机观测，不作为跨机器的固定时间断言；原始命令、日志和报告保留在仓库外。

## 上下文类型推断

- 已有完整期望类型的实参直接检查；缺少上下文时，独立试算成功后的 HIR 和状态只提交一次。数组、相等比较以及 `if` / `when` / `try` 分支使用同一规则，失败只在获得新上下文后重试。
- `compiler-performance` fixture 覆盖 32 层普通调用、泛型调用、数组、条件分支、相等比较，以及空数组、裸枚举 variant、lambda 和副作用顺序的组合。
- macOS / Apple M3 Ultra、LLVM 22.1.8、release 编译器、debug Scoop 产物：原 20 层普通调用约 12.30 s，修复后首次复测 1.54 s；32 层普通调用、泛型调用、数组和条件分支分别为 0.73 / 0.73 / 0.72 / 0.68 s，32 层相等比较为 1.32 s。
- 验证通过：`cargo fmt --all`、`cargo clippy --workspace --all-targets`、HIR 1496 项测试，以及 34 个正式 CLI fixture（36 个 variant，覆盖新增性能用例、实参推断、lambda 推断和上下文枚举）。整数字面量的错误位置与诊断、跨库产物消费和运行结果均保持通过。

## 按需读取机器依赖

- 当前源码解析成功后才读取依赖 HIR；名称解析保留完整 direct/support 声明图。当前 HIR 选出实际引用的 provider 后，才读取这些 provider 及其 manifest 依赖闭包的 MIR、LIR 与物理定义，并共享已读的 HIR 和实体身份。产物仍记录原来的完整直接依赖边。
- 同一台机器、相同配置下，声明 core 和 HTTP client 但未使用 HTTP 的小库（15 个传递依赖）首次编译从 23.49 s 降到 5.04 s，修改源码后从 23.97 s 降到 4.77 s；峰值内存从约 6.64 GiB 降到 1.61 GiB。未变输入仍约 10 ms 命中缓存，语法错误约 29 ms 返回。这项选择以 provider 为粒度；实际引用 HTTP 的程序仍需读取相应机器依赖。
- 产物读取的 249 项测试通过；新增测试直接检查未使用的 MIR/LIR 成员未被读取，保留真实源码、工具和产物。46 个正式 CLI fixture 通过，覆盖 7 个性能用例、17 个实参推断用例、20 个布局依赖用例和 2 个 LIR 选择用例，包括新库的发布、下游消费与运行。
- driver 首轮 83 项测试中 62 项通过，21 项失败归于三处既有 coroutine 私有 helper 与有限支持导出断言，已在原提交 `abf17c32c` 的独立 checkout 上逐类复现。按既有契约修正后，82 项在完整 driver 测试中通过，最后一项 bootstrap 统计修正也单独复验通过；最终统一验收另记。格式化与 workspace lint 通过。

## 候选试算状态

- 参数形状不匹配时先退出，不建立 Lowerer 副本；普通函数名跳过 nominal constructor 准备。已准备的依赖泛型与 constructor 正文、属性声明、已加载 nominal 信息和来源信息共享存储；候选的新增或修改通过现有持久化容器隔离，选中后再提交，输出仍为原有完整 HIR。
- 同机串行交替编译 `scoop.std`，修复前两次为 13.54 / 13.56 s，修复后为 8.27 / 8.30 s，平均减少约 39%；峰值内存约从 1.48 GiB 降到 1.46 GiB。首次小范围共享后的采样仍发现属性和依赖选择表深复制，最终结果包含对这些实际热点的修复。
- 验证通过：格式化、workspace lint、HIR 867 项、HIR lowering 1496 项，以及 20 个正式 CLI fixture（新增候选回退与跨库泛型组合、17 个实参推断和 2 个 LIR 选择用例）。新增组合覆盖 constructor、泛型成员、闭包捕获、局部函数及不适用重载，运行结果与副作用顺序正确。

## 逐函数后端准备

- safepoint 按 body 一次分组，GC effect 表共享；函数 LLVM module 只声明实际引用的描述符、数组、全局数据和初始化单元，保留全部归属该 callable 的 C 字符串。Cone 级归属索引和 LLVM context 复用，逐函数 module 及时释放；物理对象、ODR、链接和 GC 分区不变，metadata 仍保留完整定义。
- 同机串行交替编译，最终 `scoop.std` 对照为修复前 8.00 / 8.17 s、修复后 7.60 / 7.58 s，平均减少约 6%；峰值内存约为 1.47 / 1.49 GiB。160 个公开类型与函数的独立库为 5.12 / 4.47 s 对 4.05 / 3.89 s，平均减少约 17%，峰值内存约 1.34 / 1.36 GiB。数字包含完整编译链，未把全部后端耗时归为本项收益。
- 验证通过：格式化、workspace lint、253 项后端测试（252 项整组通过，1 项旧 C metadata ABI 断言修正后单独通过），最终生命周期调整后 13 项对象分区测试再验通过。旧断言的失败已在原提交独立 checkout 中复现，按现有 ABI 9 / image 208 字节合同单独提交修正。
- 20 个正式 CLI fixture、25 个普通变体通过，覆盖函数数据引用、候选回退、跨库初始化、装箱、数组及 14 个分派用例；另在两个已构建程序上抽样 moving GC。普通验收移除继承及 fixture 显式设置的 GC stress 环境变量；不能将其设为 `0`，既有 helper 会以变量是否存在判断是否需要检查 GC epoch。
