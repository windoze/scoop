复用 `tests/benchmarks/parallel/mark-graphs.scoop` 与 `mark-phase.c`；C companion 以 `-O2 -DSCOOP_BENCH_PARALLEL_METRICS` 构建，读取真实 collector 阶段统计。每格五个独立进程，旧／新顺序逐轮交替。full 每进程 22 事件、舍弃前两次后合并 100 事件；minor 每进程 52 事件、舍弃前两次后合并 250 事件。报告 nearest-rank p95；同进程事件相关，不能当成全部独立样本。计时期间没有并行构建或本任务的其他测试，未固定 affinity。

以下暂停均为 runtime `pause_ns` 的事件差值：world 停稳之后至解锁／恢复之前，边界见 [GC-PAUSE-WORK.md](GC-PAUSE-WORK.md#1-先区分三个时间)。单 mutator，stop-wait 中位数低于本机 1 µs 计时粒度；不能据此声称多线程握手或 GUI 响应尾部已改善。

## 3. Minor 与无引用大数组

复用 `minor` 模式，`SCOOP_BENCH_NODES=4096`：旧引用数组持有 4096 对年轻 Node／Leaf，连接环并 pin 一个对象，继续分配至触发一次 minor。每事件均追踪 8192 个年轻对象、扫描 4096 个旧引用槽、晋升 229,376 bytes、实际搬迁 7027 个对象。显式设置四 worker 时 runtime 报告实际使用四 worker，不能与默认 minor 策略混淆。

大数组对照只在临时源码的 main 中额外保活 `Array<Long>(16777216L) { index -> index }`，即 128 MiB 无引用 payload；在最后检查首尾元素，以保证存活。初始化发生在计时事件之前，其他源码相同。单位 µs，单元格为 p50／p95。

| 旧无引用 payload | worker | M58 前 | M58-A 后 |
| --- | ---: | ---: | ---: |
| 0 MiB | 1 | 729／769 | 472／512 |
| 0 MiB | 4 | 686／753 | 413.5／495 |
| 128 MiB | 1 | 873／929 | 465／497 |
| 128 MiB | 4 | 814／933 | 413／454 |

单 worker、0 MiB 时 reclaim 290 → 25 µs；带 128 MiB 数组时为 290 → 23 µs，update 263 → 192.5 µs。必要旧引用扫描、晋升和 pin 结果一致；无引用数组不再额外扫描其卡表。本期没有省掉卡表分配或清零，不能将这项收益称为 footprint 缩减。

| wrapped | 后 | 21.678／21.225–22.321 | 10,400,296 | 9 | 106 | 12.92 |

所有进程 full 为零。leaf 时间约 −10.9%、分配 −38.1%；wrapped 时间约 −32.2%、分配 −74.5%，差值等价于每次任务少分配 608 bytes。修改后的 wrapped 与 leaf 分配完全相同，体现四层非尾包装的 frame／adapter 已消除；剩余 208 bytes／次附近仍包含 closure 和动态协议路径，不是零分配协程。wrapped 每进程最大主体暂停的中位数 26 → 20 µs，但累计暂停仅减少 363 µs，不能用 GC 暂停减少单独解释约 10 ms 的总收益，更不能据此外推大型 full 的暂停。

最终 executable text 708,732 → 687,516 bytes（−21,216，约 −3.0%），文件 17,266,616 → 17,012,952（−253,664）；应用 `.slib` 2,893,046 → 1,994,396 bytes。直接应用编译一次预热后三对，中位数 6.419 → 6.192 s（约 −3.5%），范围 6.400–6.469／6.181–6.226 s；用 `/usr/bin/time -l` 测得编译峰值 RSS 中位数 554,418,176 → 534,036,480 bytes（528.7 → 509.3 MiB）。这些是匹配 dev 工具的相对编译成本，不等于发行编译器的绝对时间。

该对照隔离 C2，前版已含 C1 tail forwarding；没有把两种机制的收益混算。保留源码循环 poll，普通内联会消除已展开 callable 的入口及包装操作；此次不是 D 的 poll 分块对照。真实挂起、跨线程恢复和 pending cleanup 的正确性由独立源码 fixture 验证，计时程序不包含真实异步等待或完整 GUI。

## 12. 整数内层 SIMD 与块大小选择

同机、同输入、同 core／runtime、相同 dev 编译器和 app release 配置，重新将逐轮基线 `417e661f2`、标量 64（`219a1a958`）以及完整常数内层 SIMD 的 16／64／256 放在一轮对照中。每模式预热后十一轮，奇偶轮反转策略顺序；测量期间没有并行构建／测试。16／256 只修改本次 producer 常数与对应后端上限，生成独立配套工具后已恢复原文件。运行时间仍包含进程启动、协议初始化与输出，不以 IR 指令数代替总耗时。
