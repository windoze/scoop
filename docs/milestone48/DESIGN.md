# M48 设计：缓存直接复用与编译职责收敛

状态：实施中，先于 M38。日期：2026-10-15。原调研基线：`e548b9ebe`；本轮实现基线：M46 完成提交 `6571bb4a`。

依据：[语言规范](../specs/SCOOP-SPEC.md)、[编译器与产物规范](../specs/SCOOP-IMPL-SPEC.md)、[运行时规范](../specs/SCOOP-RUNTIME-SPEC.md)和[路线图](../ROADMAP.md)。本文规定 M48 的目标合同；[历史测试清理](CLEANUP.md)规定删除与迁移范围，并附[源码隔离测试扫描清单](SOURCE-ISOLATION.tsv)。实际完成项与证据见[进度](PROGRESS.md)，设计要求本身不代表实现或测试已经完成。各批实施前先修改相应 spec，再修改实现。

## 1. 原则与交付

编译器的职责是把源代码编译成可执行文件。源码发现、语言检查、IR 变换、代码生成、必要的 runtime／ABI 数据、调用 native 工具及构建缓存直接服务这一职责；缓存和产物不是需要编译器审计的外部安全对象。

1. **有效缓存直接使用。** 输入未变化且所需输出已存在时，不重新生成、复制或读取产物内容。缓存命中判断先于源码内容读取、预处理、输入物化、编译器能力查询和链接准备。
2. **缓存只判断是否需要更新。** 根据编译输入、构建配置与格式版本决定是否失效，不对命中的产物重新检查正确性、合法性、来源、指纹自洽性或生产过程。
3. **不处理缓存被外部意外破坏的情形。** 不增加损坏检测、校验和核对、自动修复、恢复、重试、隔离或防篡改路径；不通过新增 `verify-cache`、严格模式或另一套 reader 保留这些职责。
4. **不审计文件系统权限和路径。** 删除所有者、权限位、私有目录、符号链接来源、路径逃逸、文件替换及读取前后身份一致性检查。正常定位输入、传递工具参数、创建输出和报告实际 I/O 错误仍是编译工作。
5. **删除全部源码隔离验收。** 不再以删除、移走、隐藏源码或工具后仍能消费 `.slib` 为测试目标。清理覆盖所有历史里程碑、公共测试 helper、普通与 negative fixture，以及尚未实施设计中的同类验收要求。
6. **正确性在产生结果时完成。** 源码的类型、访问域、effect、初始化、泛型和 ABI／GC 规则仍由相应 stage 完成。后续消费已经产生的结果，不为证明前一阶段做过正确的工作而完整重放。

M48 必须同时完成库缓存、编译依赖、runtime／native 对象和最终可执行文件的复用。只让 `scoopc` 少启动几次、而每次仍复制所有输入并重新链接，不算完成。

本期不引入远程缓存、分布式构建、缓存守护进程、持久编译服务、文件监听器、通用资源预算或认证体系。Lowerer 的重载候选深复制属于另一项前端性能工作，不作为本期完成条件。

## 2. 当前问题与调研依据

基线使用 Apple M3 Ultra、当前 release 版编译器，编译的 Scoop 程序采用 debug profile。core 冷构建为 14.76 秒，std 冷构建为 26.78 秒；core／std 全缓存命中仍分别为 0.53／1.29 秒。空 `main` 完全命中编译和 runtime 缓存后仍用 3.75 秒，进程树峰值 RSS 约 1.36 GiB。

| 当前路径 | 观察 | 本期处理 |
| --- | --- | --- |
| `snapshot/staging.rs::write_verified_file` | std 暖构建主线程样本 81% 在临时文件写入与验证，其中 70% 在同步等待 | 命中时不创建输入副本；删除写后读回、同步落盘和只读封存 |
| `compiler.rs`、`child.rs` | 能力查询前后、每次编译前后完整读取并哈希 scoopc | 工具未更新时使用已记录配置；删除执行前后重捕获及整个可执行文件的常驻副本 |
| `cache/store.rs`、`cache/validation.rs`、`.slib` reader | 同一缓存字节多次读取、哈希、校验目录／收据，再复制到 staging | 用构建记录作更新判定，命中返回产物位置与已保存摘要 |
| `layout_compile_closure`、`layout_link_objects`、`layout_link_symbols` | 空 main 编译子进程的对象与符号复核占样本约 54.2%；暖构建父进程为 22.7% | 删除缓存消费中的生产重放、对象证明复制和摘要核对 |
| `codegen/atom_boundaries.rs` | core／std 子进程样本约 45.5%／26.4% 在边界路径，几乎全用于反复建全局索引 | 删除只服务已退役验证的边界；仍有实际用途的索引只建立一次 |
| `build.rs`、`program_link.rs`、`materialize.rs` | 编译命中后仍读取完整 Link 闭包、重建临时对象、调用链接器、复制可执行文件 | 最终链接也先判断更新，直接复用已经生成的文件 |

这些百分比是不同进程的调用栈样本占比，包含 I/O 等待，不可相加或用来承诺固定加速比。M48 以第 10 节的实际工作量与同机测量验收。

## 3. 缓存的更新判定

### 3.1 构建记录只保存下一次构建需要的信息

在现有缓存中保存一份普通构建记录，记录编译输入的观察值、已使用的配置、依赖构建结果、生成物位置，以及后续编译／链接真正需要的摘要。它不表示产物经过认证，也不附加收据摘要或验证资格。

同一工作区、Cone、Production／Test 用途、target 和 profile 的记录可直接定位。宿主路径可以作为本地记录的定位信息；它不因此进入语言实体 identity。输入记录与 HIR／MIR／LIR 的语义 identity 分开，不为缓存状态增加语言身份或 ABI。

| 输入 | 判定更新所需的信息 |
| --- | --- |
| manifest 与命令配置 | 选定 manifest、有效配置、用途、目标、优化模式及影响编译的选项 |
| Scoop 源码 | 选中文件集合、逻辑文件名、修改时间与大小；增加或删除选中文件也失效 |
| 源码依赖 | 当前已选依赖关系与构建记录中保存的实际依赖输入键／必要语义摘要 |
| scoopc、generator 与 native 工具 | 实际选中的程序、修改时间与大小、记录的工具／协议版本和生效参数 |
| 用户 native 与 runtime 输入 | 源文件、上次真实编译得到的头文件依赖、include 配置及会影响文件选择的目录状态 |
| 最终链接 | 实际采用的 Cone 代码结果、runtime／native 结果、目标与链接配置、库选择及工具输入 |

文件元数据仅用于发现正常输入变化，不比较 inode、owner、权限或读取前后状态，也不以重新读取内容确认元数据是否可信。人为修改内容后恢复时间戳、外部改写缓存字节等不属于本期处理范围。

源码发现可以为判断集合变化进行必要的目录枚举和输入 metadata 查询；不能把全部源码内容读取、预处理或产物扫描藏在“检查更新”里。未选中的源码内容、程序 argv、测试过滤参数、输出显示形式不使编译缓存失效。

manifest 未变化时使用记录的解析结果；变化后解析一次，按有效配置区分 Production／Test 和 target。只改测试配置不能使未变化的生产依赖重新编译。新选中的依赖、文件或工具按本次有效配置处理，不沿用已失效的发现结果。

源文件或工具的修改时间／大小变化可以直接使相应输入失效；不为恢复一个可能内容相同的命中而强制读取整个工具文件。确需读取的当前源码，其字节同时用于 parser 和正常的身份／语义计算，不另读一遍取得缓存摘要。

### 3.2 命中与失效只有普通构建含义

下列情况要求更新：记录不存在、缓存格式或工具配置版本改变、实际输入变化、所需输出不存在，或用户请求的观察结果尚未产生。

缓存记录存在且输入未变化时直接采用记录，不把它与 `.slib` 内容重新交叉证明。不重新计算 artifact／member／object hash，不重新检查缓存 warning 的语义来源，不重新读取对象来确认“这真的是上次的输出”。

读取少量构建记录是查找缓存所需的 I/O，不是打开整份编译产物。按已知 schema 解码所需字段时使用普通安全的读取和错误传播，不新增 canonical 重编码比较、完整引用验证或损坏诊断阶段。实际读取失败直接报告现有读取错误；不因此扫描、修复或重建另一份“更可信”的缓存。

输入缺失按当前源码构建请求报告普通缺失错误；所需输出缺失则生成该输出。这与检测输出内容被破坏是不同工作：不读取输出内容来寻找损坏，也不维护“损坏缓存不可视为 miss”等历史规则。

旧缓存通过新的格式版本／namespace 自然失效，不解析或迁移旧证明、收据和验证状态，不为兼容旧缓存同时维护两条生产路径。具体版本号在实施时接续最新实现，不预占其他里程碑的编号。

### 3.3 native 与工具探测也必须服从更新判定

用户 C/C++、runtime、启动代码的依赖发现结果随真实编译保存。后续先检查已记录的源码、头文件、编译配置与影响 include 选择的目录状态；没有变化时，不再调用预处理器或读取全部头文件。新增、删除或改变 include 搜索输入后，重新做必要的正常依赖发现和编译。

`scoopc` 和 native 工具的能力／版本只在首次需要或工具输入变化时查询一次并记录。缓存全部命中时不启动工具来重新确认同一版本，也不完整读入工具二进制计算指纹；程序能否启动由真正需要执行时的 OS 调用结果决定。

M47 generator 使用同一规则：保存实际使用的程序与配置，输入变化使使用它的 Cone 更新；未使用的注册项不影响结果。命中不启动 generator、不读回其程序内容。缺失一个上次实际使用的工具属于构建输入变化，不能靠删除工具来建立“无工具仍成功”的特殊验收。

## 4. 构建数据的流转

### 4.1 先查缓存，再准备实际工作

```text
读取请求与必要的构建记录
  → 检查输入集合、metadata、配置和依赖是否变化
  → Cone 未变化：取得已有结果的位置与摘要
  → Cone 需更新：读取其源码并正常编译一次，保存结果
  → 库所需输出已存在：直接返回
  → 程序链接输入未变化且输出存在：直接返回／运行已有文件
  → 链接需要更新：按需取得已有对象和必要元数据，链接一次
```

删除 `Preparer::run` 在命中判断前为整图捕获、复制、封存所有源码和依赖的顺序。parent 传递当前选中的输入清单和实际文件位置；scoopc 只读取这次编译需要的源文件与依赖 section。不要求把完整工作区制作成一份私有、不可变的临时镜像。

编译器不防御其他程序在构建途中替换输入，不反复检查文件稳定性，也不因这一假设保留全量字节副本。正常的源输入错误和工具失败仍终止当前构建，不能把失败当作成功命中。

### 4.2 已生成的内容只保存和读取必要次数

每个实际编译阶段直接把已生成的数据传给后续阶段，摘要在产生结果时计算并保存。发布 `.slib` 不重新打开自己的归档以证明写入正确，parent 不重新执行与 child 相同的产物正确性验证。

每个消费进程只有一个普通的按需 artifact 数据入口。同一产物的同一 section 首次需要时解码一次，后续借用或共享该结果；不能由 HIR、MIR、LIR、Link 各自打开全包，再分别建立一份相同闭包。缓存只需要返回库文件路径、或最终可执行文件已经命中时，不打开该包。

不同编译子进程确实需要同一份依赖数据时，允许各自首次读取必需 section；M48 不为了消除进程边界的必要读取而新增驻留编译服务或共享内存协议。parent 也不为了向 child 提供路径而预先读完依赖。

对象在首次生产时保存在缓存结果的稳定位置，后续链接直接传递这些对象路径。现有 native linker 必须使用普通文件时，由首次生产保存这些文件；不能每次链接都从 `.slib` 解包、改写、哈希或再物化一遍。`.slib` 的必要打包与面向 native 工具的文件输出各自只在结果需要产生时完成。

缓存模型不再强制长期持有完整 `.slib`、scoopc 二进制、每层验证结构和两份对象字节。数据生存期由实际使用决定；不再保证删除原始文件或缓存后构建仍能继续。

### 4.3 发布与并发只解决正常构建问题

保留普通构建锁避免两个本机构建同时生产同一结果。取得锁后重查更新记录，已有结果即可使用；不比较两份完整产物或建立“获胜者等价证明”。不同输入的结果不得覆盖正在被本构建使用的同一输出文件。

新结果在临时输出位置生成，工具成功后通过普通 rename 完成发布，再更新构建记录。失败不发布部分结果。删除每个输入／缓存文件的 `sync_all`、目录同步、写后读回、只读权限封存和目录内容审计；不承诺掉电后的缓存持久性或恢复。

用户要求一个尚不存在的输出位置时，可以执行一次满足输出要求的正常发布；记录该位置与结果的关系，后续命中不重复复制。默认输出、跨目录输出或 `-o` 都不能为了“用户可能改坏输出”而重复读取、哈希和覆盖未变化的文件。

## 5. 编译正确性与缓存消费的边界

### 5.1 在相应阶段保留的工作

parser／HIR 完成当前源码语法、名称解析、类型、语言访问域、泛型和 effect 检查；MIR／LIR 产生完备控制流、布局、调用及 GC 数据；codegen 生成满足后端合同的对象；链接执行本次实际符号、ODR 选择、startup、native 与 runtime 连接工作。

generator 新返回的 AST 仍是本次需要编译的输入，必须按普通语言规则检查。这与读取已经编译完成的缓存不是同一边界。

编译输出需要的 target／ABI 配置、typed identity、重定位、运行时表和实际有用的语义摘要继续存在。它们是编译和运行使用的数据，不是来源授权。不能把取消缓存验证误写为放宽源码类型规则、取消移动 GC 根更新或不再生成合法目标文件。

### 5.2 从缓存消费和发布中删除的工作

| 现有行为 | M48 决定 |
| --- | --- |
| 整包／成员／对象 hash 与记录的摘要逐项比对 | 删除；更新判定使用记录的输入信息 |
| 收据绑定、重复的 child 成功产物字段核对、Graph／Compile／Link 验证资格转换 | 删除仅用于证明结果可信的结构与路径；保留实际结果数据和进程成功／失败状态 |
| 同一依赖的名称、类型、引用、布局与生产语义完整 replay | 删除消费中的重放；读取已保存的必要数据 |
| `layout_link_objects::verification::replay` 与 `layout_link_symbols::verification::replay` 中的产物复核 | 删除缓存复核；把真正参与本次链接选择的数据读取留在普通 Link 输入中 |
| `normalize_final_scoop_lir_objects_v1` 的 final／provisional 双份复制、指纹清零、重填及最终字节比较 | 缓存消费中整条删除，使用已完成对象 |
| 为匹配已有证明而 clone／深比较 `Verified*` 闭包 | 删除；正常数据按实际需要共享，不以另一种命名保留证明链 |
| 对刚写出的归档、缓存文件或最终可执行文件再做完整生产验证 | 删除；工具失败照常报告，必要后端契约在产生结果时处理 |

读取已生成数据时，数组索引、长度转换与内存访问仍使用安全实现；这是实现本身不越界的要求，不允许据此恢复一个额外的缓存内容验证阶段。通用解码库自然返回的错误可以传播，不为恶意或意外损坏输入建立单独合同和测试矩阵。

`.slib` 仍可作为编译中间产物与已有显式输入，但不再承担独立分发认证或“源码和工具都消失后仍保证可用”的产品合同。相同产物读取使用同一普通入口；不为显式 locator 建立另一套不可信产物认证 reader。M48 不因清理测试额外删除普通独立链接命令，也不以维持其历史隔离模式为保留验证链的理由。

### 5.3 清理验证附带的全量索引

先删除没有真实消费方的验证器边界、对象证明索引及其 metadata。仍用于生成代码、实际 relocation／GC 数据或链接选择的边界表，在同一份不变 surface 上只建立一次，按本次所需 atom 查询；禁止每个函数、每类 metadata 重扫整 Cone。

同时复用同一 module 已产生的 runtime scan 计划和必要对象索引，不为新的包装层重新建立同样的数据。没有实际输出的调用直接结束。该工作保持 stage 只经 IR 数据契约通信，不把上游 stage 的实现依赖引入下游。

## 6. 文件系统与工具边界

删除或缩减 `ImmutableInputSnapshot::capture` 的稳定文件证明、`capture_no_follow`、`revalidate_executable`、`ensure_executable`、staging 私有目录／只读树检查、缓存锁文件来源检查及 `OutputLocation::check_inputs` 的文件身份审计。

路径只用于正常源文件选择、建立 SourceLocation、定位依赖、查找 native 输入、传参和输出。保留这类实际功能所需的词法处理与语言逻辑名称；不检查路径是否位于“可信”根下，不以 symlink 指向根外、inode 变化或所有者信息决定能否编译，不重复 canonicalize 后证明路径没有被替换。

创建文件、执行工具或读取输入时直接使用 OS 接口，失败报告对应 I/O 错误。生成可运行文件所需的执行位、对象段布局和装载格式属于输出工作；它们不要求先审计输入和缓存权限。语言的 private／protected 可见性仍是语言规则，与文件权限无关。

不新增环境净化、路径授权、文件保护或进程隔离策略。为正确选择 target、SDK、C/C++ driver 而使用的显式参数和环境仍照常传递；临时目录只用于确实需要生成的工作文件。

## 7. 最终链接、运行与观察输出

### 7.1 最终可执行文件是缓存结果

构建记录保存最终链接实际使用的编译结果和配置，并保存 executable、必要链接摘要及用户输出的位置。下一次先根据已保存的依赖结果和当前输入判断是否更新，不能为了计算链接键先读取、验证和物化完整 Link 闭包。

全部未变化且所需 executable 存在时，不调用 `read_program_link_closure`、不生成 startup C／image tables、不创建 response file、不调用 C compiler／linker、不复制或重新读取 executable 内容，直接返回已有文件。

链接输入变化时，只重新进行需要更新的链接工作。仅 native 库、runtime 对象或链接选项变化，不应重新编译无关 Scoop Cone；仅某个源码 Cone 变化，也不重新构建未变化的 runtime。最终所选对象、启动代码及运行时关系由本次实际链接需求决定。

库路径搜索还须观察影响实际选择的输入目录；增加更优先的真实候选或改变显式配置时重新选择。这个发现职责不能扩展成扫描、认证整个缓存或文件系统。

### 7.2 run／test 直接使用已有文件

`run` 与测试入口执行本次构建确定的已有或新生成 executable，不再制作私有 execution copy。argv、cwd、stdio、测试事件通道和实际 exit／signal 的行为保持；保留 argv[0] 约定不需要复制二进制。

同一构建请求失败时仍不能执行旧结果；成功命中已有结果本身就是成功构建。测试过滤、`--list`、`--no-run` 不触发无关重新编译和链接；列表只读取已有测试目录信息，不扫描整个产物。每次运行的测试事件和输出文件不是编译缓存，不缓存测试运行结果。

### 7.3 显式 dump 只补所需结果

已有且对应当前输入的 AST／HIR／MIR／LIR dump 直接复用。缺少所请求的 dump 时，只做产生该观察结果所需的前置编译工作；不因为请求观察就重新生成有效的机器对象、`.slib` 和 executable。源码变化使对应观察记录失效，诊断依然使用当前请求的定位信息。

## 8. 历史测试全部清理

按 [CLEANUP.md](CLEANUP.md) 与扫描清单处理全部命中项，不能仅删除目录名带 `artifact-only` 的少数测试。删除源码再编译下游、删除源码再独立链接、移走 sysroot／runtime／工具、删除原始产物却要求内存副本完成后续阶段，都不再作为保证。

纯粹验证这些历史能力的 case 整体删除。混合 case 中有效的语言、FFI、GC、运行和诊断断言迁到源码保留的真实多 Cone 构建或缓存复用场景，去掉删除／隐藏步骤和隔离成功断言，不只是给旧 case 改名。

同步删除缓存损坏、伪造收据、替换编译器、权限及路径攻击等防御性测试。保持真实输入变化的失效测试、选中输入不存在的普通诊断、编译失败不发布结果，以及正常并发构建协调测试。测试结束后的目录清理不是源码隔离场景。

M47 不再要求无上游源码或移除 generator 后消费成功；正常下游消费不重跑上游 generator，通过源码与工具保持存在且记录实际调用来验证。已完成里程碑的历史验收记录可保留为历史，不再作为当前新增／保留隔离测试的依据。

M48 与 M46 的库行为、M47 的生成算法没有功能先后依赖。实施在当时主线接入，复用 M47 已落地的真实工具输入；若尚未落地，先在设计中采用本合同，不增加提前实现 generator 的前置。

## 10. 验收

### 10.1 真实构建行为

| 场景 | 必须观察到的行为 |
| --- | --- |
| 库连续构建两次 | 第二次只做更新判定并返回现有结果；无 scoopc、产物内容读取、源码／产物复制、缓存重写 |
| 程序连续 build／run／test | 输入和 executable 未变化时无编译、预处理、runtime 构建、链接或 execution copy；实际运行仍产生正确结果 |
| 修改、添加、删除选中源码 | 更新受影响 Cone 及实际依赖结果，运行体现变化；未选中源码变化不触发重建 |
| 修改依赖公开声明／模板或实现 | 按真实编译／代码依赖使下游编译或链接更新，不能继续使用旧 executable |
| 修改 native 头文件、include 选择、runtime 源码或链接库 | 更新真正受影响部分；其余 Scoop／runtime 缓存复用 |
| 修改 target、profile、用途、工具或实际 generator 配置 | 对应记录失效；不同模式不互相冒用结果 |
| Production／Test 与过滤 | 测试专属输入不使未变化的生产依赖更新；过滤和列表不重编译 |
| 所需结果不存在、另选输出位置 | 只补齐所需结果或执行必要发布，不作损坏内容检测 |
| 构建失败与普通并发 | 失败不发布／运行旧结果；相同输入的等待者复用成功结果，不比较整份文件 |
| 当前输入的观察输出 | 复用已有 dump；缺失时只产生所需观察，不重做有效机器产物和链接 |

这些场景通过真实源码、正式 CLI 和已有 runner／观察记录验证。源码与工具保持存在；通过调用次数、文件写入情况和结果行为证明复用，不能靠删掉源码或把工具换成损坏文件证明没有访问。I/O 的只读采样或小范围测试替身只用于验证本次改动，不在生产代码中建立逐操作预算和常驻跟踪框架。

### 10.2 必须消失的工作

全命中构建中不应出现完整 `.slib`／对象读取、SHA 内容核对、`validate_cache_entry`、生产 replay、staging 写后读回、工具二进制捕获、native 预处理或最终链接。读取必要的小型更新记录、查询输入 metadata 和确认所需输出存在不计为产物内容读取。

真实编译中不应出现“每个函数重新建立整个 atom 边界表”；读取同一依赖后不应为验证而产生多份相同 IR、重定位／注册闭包或 final／provisional 对象。源码隔离和缓存损坏防御 case、辅助代码和未使用期望文件全部清理，不能留作跳过的验收组。

### 10.3 性能与回归口径

同机、同一 release 编译器和相同 Scoop profile 测量 core 冷／暖、std 冷／暖、空 main 冷／暖、一个真实多 Cone 程序，以及含 native／runtime 输入的增量构建。每组至少五次独立命令，分别记录冷缓存与暖缓存的中位数、范围、进程树峰值 RSS、实际编译／链接调用数；不要把两个工具优化模式混在一起。

以结构验收为首要条件：有效库产物零重读／复制，全命中程序零重新链接，依赖按需读取，遗留验证链消失。在此基础上报告实际时间、内存与样本热点变化，不预先承诺由现有样本比例直接推导的加速倍数。

实施按 Rust／Python 变更先格式化与 lint，再运行相关测试、fixture runner 规则测试和迁移后的正式 CLI 全量。覆盖 Darwin、Linux GNU、Linux musl 的适用构建与缓存场景；ABI、GC、FFI 和源码诊断回归继续验证生成程序的实际行为。测试减少的数量必须能对应退役场景或迁移记录，不能以减少有效语言覆盖换取通过。

M48 完成时，正常构建路径只有“判断哪些输入变化、完成必要编译和链接、直接使用已有结果”。不存在为了证明缓存未被破坏而恢复的额外阶段。
