# 普通 GC 省去搬迁覆盖登记

基线为 `efd7de641`。在接口 SSA、存活清单直接指向当前副本和数组屏障优化之后，trees 采样仍显示引用回写前的元数据查询与 claim 成本。本项只处理这一条重复工作，复用现有存活清单和诊断配置。

原子首次标记已保证清单条目唯一，全部目标预留成功后的复制阶段已把条目改为当前副本。普通串行／并行 update 直接消费这些事实，省去逐条目的对象定位、身份重查、`scanned` 登记及仅为验证保留的转发失败分支。真实 roots、字段和 remembered slots 仍按原规则定位并转发；pin、survivor、数组任务划分、预留失败和 worker 生命周期保持。

覆盖检查、专用 bitmap／large 标志和它们的分配、清零、释放由预处理条件完整排除。现有 `--enable-gc-stress` 构建能力或显式 `SCOOP_GC_VERIFY_HEAP` 保留原覆盖验证；仅启用启动诊断不启用此验证。全部 profile 的普通 runtime 默认采用，无新优化开关。runtime contract 19、managed 对象／根／scan 和 generated-code ABI 保持；四个系统库逐字节复用，只需重建 runtime 并重新链接。

## 正确性与生成结果

两机先格式化、workspace Clippy 和相关 C 警告检查，再各通过 7 项定向测试。串行／并行回写在普通、单独 heap 验证、stress 三种构建下覆盖实际 minor 搬迁、1／2／4／8 worker、共享图、引用数组、pin、native 根与字段别名及 remembered slots；原存活清单、worker 创建失败和 stable 引用检查继续通过。新增产物测试以 `-O0` 编译，直接断言未剥离对象中普通配置没有三个覆盖验证函数，两个诊断配置仍包含它们。

三目标各通过 `gc-correctness/interface-ssa` 和 `gc-correctness/poll/reference-arrays`，fixture runner 各记录 3 个变体、12 次进程调用，含 debug／release、moving／minor、父接口投影、数组复制和可选 survivor。单独诊断确认接口用例各实际搬迁 10,648 B，数组用例均实际执行 minor 与复制；普通性能程序也真实发生搬迁。没有完整验收。最初给原手工栈帧 C 用例额外添加 `-O2`，触发其栈范围错误；最终沿用该载体原有编译设置，正式程序仍使用正常 release。

每目标核对四种 runtime 的全部对象：普通和 startup-stats 配置均无覆盖验证符号及相应错误文本，stress 两种配置保留；预处理结果也无专用字段／操作。八程序的 MIR、LIR 和符号映射完全相同。最终代码中串行 `relocate_live_object` 和并行 `scoop_gc_update_live` 各消除一处 claim 调用；ARM64 两函数分别从 28／139 降到 19／133 条指令，x86_64 从 27／177 降到 22／176。

dispatch、lambdas、List<Long>、接口数组和 class 跨调用循环的指令及栈访存计数均保持。dispatch 仍为 ARM64 29 条指令／4 条栈访存（poll 快路径 2 条），x86_64 35／5（快路径 3）；没有把既有 SSA 的成果重复计入。部分反汇编显示名随链接地址变化，应用指令数量不变。

M3 Ultra／LLVM 22.1.8 与 nuc12 i7-12700H／LLVM 22.1.2 实机；每目标一对预热、五对 AB／BA，正常 release、不启用 stress，没有固定 CPU affinity 或频率。同源码、编译器、系统库和接口布局，仅替换 runtime。下表为墙钟中位数变化，负值表示耗时降低。
