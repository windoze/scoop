# 数组初始化屏障消除

在 `b05c4c7e7` 的年轻对象初始化证明上，继续处理 typed 数组字面量、clone 和 vararg assembly。沿用 **release 默认分配优化**，不新增开关、对象字段、GC root、ABI 或测量代码。已有库对象需要重新编译才能获得该生成优化。

## 实现与边界

- 三条路径保留 `managed_alloc_value` 的实际 TLAB 成功条件。在操作内部完成初始元素写入后，只有慢分配执行原范围屏障；成功 bump 来自 nursery，写入前后没有用户调用或 safepoint，不产生 old→young 边。
- 字面量实参仍提前按序求值；clone 保留既有完整 stride memcpy，assembly 保留原逐元素复制。分配后的源对象及 interface object 分量仍消费恢复后的引用，源／目标地址不跨 GC 保存；长度、padding、溢出、独立数组身份和原 poll 保持。
- 无引用、ZST 和已知空 payload 不新增判断。慢分配、大数组、共享 C 后备、普通 ArraySet、带用户 initializer 的构造，以及向外部数组发布结果，仍保留所需屏障。年轻事实不传出当前 typed 数组操作。

实现只调整 codegen 的数组分配／复制及原范围屏障 helper，复用既有 `initialization_barrier`。MIR／LIR、晚期 aggregate 分解、RS4GC 和 runtime 均未改变；三个目标的对照 MIR／LIR 逐字节相同。

## 定向验证

- 两机格式化、release workspace Clippy 与各 10 项数组单测通过。覆盖实际快分支与屏障 guard 一致、三种引用初始化、debug 保留屏障、标量／空数组不增加判断、ZST、长度上限与源根重读。收尾调整测试数据的局部 ID 取得方式后，仅补跑两个相关测试。
- 三目标各通过 gc-writes 的 debug／release、普通／moving／minor，共六次程序运行。新增 2,048 项多引用聚合 clone 与 2,050 项 assembly，minor 后读取首、中、尾项及接口身份，覆盖大数组慢分配；原小数组、装箱、构造中 GC、原子和旧对象写入继续通过。
- 额外统计运行确认 moving 模式有 8,228 次 full、搬迁 1,618,613,600 B；survivor 组合有两次 minor、三次 full，检查通过。统计未提供 survivor 保留数量，不推断该项。Linux 首次 fixture 被本次文件同步附带的 AppleDouble 文件拦住，移除对应附带文件后通过；没有生产实现故障或全量验收。
- ARM64 与 x86_64 机器码都以实际 fast 条件跳过初始化范围屏障，慢分配后重取源引用，再复制与标记。外部结果数组的屏障保留；无引用两种 clone 的机器指令数不变。x86_64 保留年轻条件会占用寄存器并影响保存／重载，未把静态指令条数当作动态成本。

## 性能与分配

[copies.scoop](../../tests/benchmarks/arrays/copies.scoop)每轮把新数组发布到 256 项循环数组。小数组八项，spread 在两端各追加一项；大数组为 2,048 项、49,176 B。普通模式一千万次，大数组两万次；输入构造在计时外。基线与候选使用相同源码、同一份预编译 sysroot 及其 92 个 runtime 对象，未重建依赖库来混入其他生成变化。

ARM64 为 M3 Ultra／LLVM 22.1.8；x86_64 为 nuc12 i7-12700H／LLVM 22.1.2，GNU 与 musl 分别实测。正常 release，一对预热、五对 AB／BA；不固定 CPU，不开 GC stress／统计。下表为内核毫秒中位数及变化，包含分配、复制、发布和 GC，不代表显著性或单次屏障周期。

| 引用字面量 | 118.874→99.850（−16.00%） | 174.876→156.076（−10.75%） | 189.608→161.152（−15.01%） |
