# 数组搜索与提前退出循环

本项延续含条件分支的数组优化，解决 `find`、首次不相等、遇到条件后停止写入等循环仍逐元素 poll 的问题。普通 `break`、`return`、异常及清理语义保持，语言行为见语言规范 8.7，分块及 roots 契约见实现规范 2.19、运行时规范 3.2。

## 选择与转换

从唯一 latch 沿前驱取得当前迭代的自然循环区域，止于 header。继续迭代的区域须单入口、无环，唯一加一更新支配 latch；外来入口、内部循环、多回边及不明确归纳变量继续保留。出口可以位于更新前，不必执行剩余迭代。

范围事实先折叠已证明的数组检查，未知条件仍按源程序顺序执行。稳定的其他数组继续通过长度 guard 选择完整块，guard 失败只选择原 checked 正文，不提前抛出异常。首次命中后不读取后续元素，不执行后续写入；异常前已经完成的前缀保持。

完整块只复制继续迭代的有限区域，出口共享原代码及其调用、分配、抛出和清理。私有临时值取得新身份；出口读取的值及循环携带值使用原 typed local，由正常后端合流，保证退出时取得本轮值。原 header 保留 poll，每个内层最多 64 次；没有新 safepoint、裸指针或根的保存机制。LLVM 的显式向量化选择仍要求所有路径到达 latch，不额外许可搜索循环投机访问。

该能力沿用 release 默认设置，不增加优化等级或 `.slib`／runtime ABI 字段。运行收益、静态空间、编译成本及未命中边界以同一源码的基线与候选产物对照记录。

## 定向验证结果

- 本机与 Linux 各通过 58 项 MIR 优化回归，格式化与 workspace Clippy 通过。新增提前退出及本轮快照专测，正常退出的最终临时值也可共享；绕过更新、内部循环、不一致快照、非单位步长和 NoGC 的原合同保持。
- Darwin ARM64、Linux GNU／musl 各通过新的优化／GC 两组 fixture，以及受影响的条件数组两组回归；每目标共 6 个变体、24 次进程调用。范围包含 debug／release、零长度、1／63／64／65 及更长数组、多个匹配取首次、未命中、别名、严格浮点、短数组提前命中、越界前已写前缀、出口调用／构造／finally 和并发 moving／minor 收集。退出分支中的显式收集之后仍能取得正确的原数组和元素快照。
- 检查实际 MIR、LIR 与机器码：六个主要搜索／前缀函数从逐元素 poll 变为 64 次以内的标量内层，原入口及循环 header 的 poll 保留；数据匹配后直接跳出，完整内层不含 poll 或调用，已证明的数组检查消失。其他数组的长度条件失败时仍执行原 checked 路径。未知索引的 `readSnapshot` 现在能分块，但检查失败出口继续保留，错误分支仍按原顺序抛出。
- 实际计时中 `findIndex`、`findValue` 和直线求和已经内联进 `exercise`，检查并保留了这些副本的 MIR／LIR／机器码。两个搜索增加完整块；其余四类内核仍通过原调用执行。浮点累加没有 SIMD 或乘加融合，LLVM 的选择规则没有放宽为投机读取。
- 三目标各 110 条 TD／接口表／类型布局记录保持；9 个函数的 LIR poll 身份及 live 集合相同。17 种负载的分配字节、nursery 字节、minor／full 次数、晋升／复制字节、root slots、dirty cards、old reference slots 和 traced objects 均相同。普通 NoGC 对照的 LIR 保持。

初次 Rust 验证暴露的是仍断言“外部读取临时值必须拒绝分块”的旧测试；按新共享值合同更新后闭合。没有扩大到全量验证，未运行完整 workspace tests 或全部 CLI fixture。

## 运行与成本

以 `b391eef85` 的工具和本项工具编译同一 [基准 Cone](../../tests/benchmarks/arrays/early-exit)，消费相同预编译 sysroot。每个模式预热一对后测五对 AB／BA，GC 诊断另跑；Linux 固定 CPU 4。正常长数组为 65,536 元素、128 轮，首项命中及单元素数组为 100 万轮；初始化在阶段计时前。下表为阶段墙钟中位数变化，负数表示耗时降低；这些是本组负载的描述统计。

| 内核 | Darwin ARM64 | Linux GNU | Linux musl |
| --- | ---: | ---: | ---: |
| 末项命中，返回索引 | −71.68% | −48.85% | −45.48% |
| 返回本轮元素快照 | −71.77% | −39.41% | −40.31% |
| 两数组首次不相等 | −74.32% | −51.61% | −52.10% |
| 命中前写入目标数组 | −68.65% | −21.74% | −21.21% |
| 严格 Double 累加后 break | −64.17% | −16.16% | −16.51% |
| 命中后构造结果对象 | −74.08% | −44.34% | −38.71% |

这六类负载的整进程耗时降低 5.34%～30.13%。未命中、中间命中、两参数引用同一数组也获益，阶段耗时降低 45.08%～73.86%。

首项命中仍支付分块选择成本，三目标阶段变化为 +2.07%／+16.57%／+29.71%，相当于每次调用增加约 0.040／0.214／0.382 ns；整进程变化为 −1.22%／+2.42%／+2.14%。单元素组变化为 −2.50%～+8.18%，最大绝对回退约 0.219 ns／调用。直线求和对照变化 +2.42%／+2.56%／+0.28%，NoGC 对照 −0.05%／−0.16%／+0.04%；保留这些结果，不将代码结构不变解释为运行时间完全不变。

## 默认策略与后续边界

本项复用既有分块、范围证明和 local 合流，代码与编译成本较低，长遍历收益覆盖三个目标，作为 release 默认能力交付。首项命中与短路径的实测成本单独保留，后续优化第一轮选择时继续对照；本项没有增加布局框架、优化等级或 PGO。

继续迭代区域内的未知调用、分配、EH、引用／聚合元素，以及多回边、内部循环、非单位步长和变化上界仍受原限制。共享出口不等于一般部分逃逸或任意循环变换；搜索循环的 SIMD 也没有在本项交付。

原始产物、日志与样本保存在各机 `tmp/program-performance/early-exit-arrays`，不提交到文档目录。
