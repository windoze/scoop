# 有界数组初始化内核

## 范围与依据

优化决策报告显示，真实 ArrayList 遍历的 `get` 因累计 caller 增长额度保留。此项不提高全局内联阈值，也不把数组初始化和一般集合遍历混为同一结果；先推进调研 B2 中已有明确输入的整数／Boolean 数组内核。

`Array<T>(size) { index -> value }` 的 scalar initializer 经普通内联展开后，MIR 仍通过多个无条件跳转块连接循环正文。元素写入的合法索引已经由构造循环保证，但现有 poll 分块只接受单块整数运算，因而每个元素仍执行外层 poll 检查。

## 设计

复用现有 release 默认的 64 次分块，不增加选项或替代布局。识别唯一前驱的直线 header／body 链，只在整个循环满足原归纳变量、稳定上界、唯一回边及局部使用条件时合并。保留原 header poll、语句顺序和源码位置，重分配被复制的正文临时值身份。更新证明只解释正文中单次定义的私有临时别名，保留重赋前已经计算的快照含义。

允许整数／Boolean 的 MIR 数组元素操作和长度读取，排除调用、分配、异常分支、引用／聚合元素以及 EH。此项不做一般 bounds-check elimination：尚有动态检查的下标循环保留原路径，带副作用或可能抛出的 initializer 也不取得免 poll 资格。零次、负长度检查、尾部不足 64 次以及整数回绕均沿原语义。

LLVM 只为结构上确有常数倒计数的内层请求向量化。访存必须是从循环外 AS1 基址经 GEP 派生的普通整数 load／store；volatile、atomic、引用值和 root-slot 访问均排除。向量化由 LLVM 依赖分析决定，不伪造 noalias／readonly。数组对象仍由普通 roots 保活和移动，元素地址不跨外层 poll 保存。

实际生成代码还会在内层从根槽重读 AS1 引用。确认入口 alloca 不逃逸、使用仅为直接 load／store、内层无写入后，可将这项普通加载移至唯一外来前驱的末尾，即外层 poll／恢复之后。volatile 根恢复与逻辑根标记不动，也不提升数组元素访问；内层使用该次取得的基址，下一块重新经过原 poll。

## 定向验证

Rust 格式化和 workspace Clippy、固定版本 Ruff 通过。5 项 MIR 分块测试与 3 项代码生成测试通过，覆盖直线 CFG 合并、临时值快照和重分配、外部读取排除、倒计数上限，以及 volatile／atomic／引用访存／逃逸根槽的拒绝。代码生成测试在三个目标上验证 RS4GC 和最终机器 site，原 site 与 volatile 根恢复数量保持。

提交前补充了 `saved = 5; captured = saved + 1; saved = i; i = captured` 的回归：旧识别会用后来的 `saved` 解释快照，把实际的常数更新误判为加一。该测试先复现失败，收紧为单次定义后在 Int／Long 上通过；未将这个实验问题带入提交。

Darwin ARM64、Linux GNU／musl 各通过两组正式 CLI 专测，共 3 个 variant、11 次进程调用；未运行完整验收：

- [数组内核](../../tests/fixtures/compiler-correctness/optimization/lowering/array-kernels/fixture.toml)：debug／release 的实际 MIR 与运行结果，覆盖 0、1、63、64、65、127、128、129、1025 个元素，Long／Int 回绕、Boolean、只读／可变数组，以及负长度、零次副作用、异常停止、越界前已写前缀和引用元素保留路径。
- [数组根与并发 GC](../../tests/fixtures/gc-correctness/poll/array-kernels/fixture.toml)：两个 callback mutator 各初始化并逐项校验 64 个 2049 元素数组，另一线程请求 GC；moving／minor 均通过。另核对真实 `generate` 的 MIR，确认被测初始化确实已分块。

最初无间隔持续请求 full GC 的测试有超时；相同源码在未修改基线也复现，线程采样显示 collector 持续收集、mutator 反复停在 poll。加入 100 µs NativeSafe 请求间隔后，基线和最终用例正常完成，三目标 moving／minor 通过；这里只调整测试调度，没有修改 runtime。原失败、采样与闭合结果一并保留，不将早期失败批次记作通过。

## 生成代码与运行测量

对照为 `c60a9bd26` 和本项实现，均使用普通 release 与生产 runtime。Darwin 使用 M3 Ultra／LLVM 22.1.8；GNU／musl 使用 nuc12 的 i7-12700H／LLVM 22.1.2，采用各自的基础目标，不使用 `-march=native`。固定一个 GC worker，GC 统计单独运行，不混入计时。

[初始化基准](../../tests/benchmarks/allocation/array-initialization.scoop)的三个模式返回完整数组并校验首尾值；每次大数组测量初始化 128 个 65536 元素数组。内核计时包含分配、GC 和初始化，进程计时另含启动／退出。每种模式有一对预热及七对交替 AB／BA 样本，双方输出一致；以下是独立样本中位数的描述比较，不是跨机器或跨语言排名。

| 目标 | Long 内核 ms | Int 内核 ms | Boolean 内核 ms |
| --- | --- | --- | --- |
| Darwin ARM64 | 14.351 → 5.601（−60.97%） | 12.880 → 2.679（−79.20%） | 11.652 → 3.074（−73.62%） |
| Linux GNU | 23.798 → 21.696（−8.83%） | 13.863 → 10.580（−23.69%） | 8.451 → 6.020（−28.77%） |
| Linux musl | 23.591 → 21.579（−8.53%） | 14.475 → 10.865（−24.94%） | 8.417 → 5.762（−31.55%） |

对应三种模式的整进程耗时分别降低：Darwin 24.94%／31.59%／26.44%，GNU 3.77%／9.40%／12.49%，musl 3.40%／8.77%／5.81%。

实际 MIR 中完整正文与尾部各有一次元素写入；LIR 每个 initializer 的入口与 header 共 2 个 poll 位置保持，动态回到 header 的频率从逐元素降为每块不超过 64 次。机器码中 Int 有向量写入，Boolean 有 SIMD 运算（x86-64 仍将结果拆为标量字节写入），Long 仍为标量内层。合格的普通根槽加载移至每块入口，volatile 恢复保持；不能把所有收益都归因于 SIMD。

另测 100000 个动态单元素数组，Long／Int／Boolean 的内核变化分别为 Darwin −11.46%／−1.90%／+7.27%，GNU +3.50%／+3.54%／+1.38%，musl +1.63%／+2.26%／+1.46%。最大绝对回退是 Darwin Boolean 的 1.499 → 1.608 ms，即约 1.09 ns／数组。动态短数组仍有分块选择和函数入口成本；静态已知不超过 64 次的循环直接跳过分块。NoGc 对照指令序列完全相同，内核变化 +0.33%／+0.09%／+0.44%，作为测量波动保留，不宣称收益。

三目标各 80 条 TypeDescriptor／类型布局记录逐字相同；Darwin 的 stackmap section 保持 819512 bytes。七个测量模式的分配量、nursery 分配、minor／full 次数与动态 root slots 在两版间相同。例如大数组 Long／Int／Boolean 的分配量约 67.11／33.56／8.39 MB，full GC 为 4／2／1 次，未通过减少分配或收集次数制造加速。对象、接口值、GC 和 `.slib` 的 ABI 均不变。

本项沿用 release 默认的有界分块与受限内层向量化：大数组在三个目标均获益，代码与编译增量有限。保留上面的动态短数组回退，不将其报告为所有输入都改善。当前不增加一套新的等级或插件框架；一般 BCE／loop versioning、浮点、引用／聚合数组和更激进的目标特化仍需各自设计与测量，高成本或收益不稳定的后续方案再确定独立开关或等级。
