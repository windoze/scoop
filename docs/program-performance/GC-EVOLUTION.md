# GC 性能与架构持续改进

## 基线与测量边界

本轮从 `cba4f23e8` 开始，复用已交付的调用点内联、接口 SSA、年轻初始化屏障消除、有界循环卡标记、分代和并行 mark／update。mm 的 `/tmp/scoop-cmp` 只作为固定源码与调查线索；其中可执行文件早于当前工作分支，不能直接作为当前 GC 基线。

起始版本确认：collector 停稳等待与所有 parker 共用条件变量，普通 park 和初始化等待每次醒来都广播；32 KiB TLAB refill 仍取得全局 heap lock；默认 nursery 上限 32 MiB、可选单阶段 survivor 默认关闭；plan／copy／reclaim 仍由 coordinator 执行。普通 Full poll 已是单次全局 acquire 读取，先前四次读取和 TLS 的描述不适用于当前普通入口。后续阶段逐项记录已解决的问题与剩余限制。

分别记录请求到停稳、world 停止、恢复通知到实际推进，以及应用观测的间隔。复用线程测试观测点和现有进度基准，测试插桩仅编入独立测量 runtime；正常计时不带观测回调。`pause_ns` 不包含完整握手和恢复，gcpause 的一万次循环间隔不是最大 GC 停顿，worker CPU 与阶段重叠墙钟不相加。

本机先验证，再补 Linux x86_64；固定源码、工具、系统库及 runtime 变体，多轮 AB／BA 对照。threads 采用固定总工作量改变线程数；bintrees、gcpause、refwrite 与不同大小／存活率的图分别归因，保留 Go／Kotlin/Native 的同机默认及可比 CPU／内存结果。编译和运行日志放仓库外 `scoop-performance-results/2026-10-27/gc-evolution`，临时源码与工具放 `tmp/program-performance/gc-evolution`。

## 阶段路线

1. 分离 collector 停稳通知与 mutator 唤醒，同一 epoch 只确认一次。覆盖连续收集、未恢复 parker、初始化等待、attach、NativeSafe 返回及 callback；测量线程扩展、系统 CPU、停稳和恢复延迟。
2. 用新基线比较 nursery／survivor 的晋升与复制成本，同时定位 remembered 扫描保留了多少额外工作。根据存活期和暂停分布改策略，不用持续扩大堆掩盖开销。
3. 评估线程块储备／批量 refill，以及 bump 连续性下的元数据发布和计数维护；先明确 GC、地址查询和统计的真实读取边界，再同步必要 codegen／ABI。
4. 按 root、remembered、mark、plan、copy、update、reclaim、VM return 消除重复工作，并实验按 block 的复制／回收并行度，计入工作区与带宽成本。
5. 实际推进并发／增量阶段：比较并发标记、非移动 full 与并发清扫的暂停收益和屏障成本，选择语义完整的阶段实现。明确根快照、分配发布、标记终止、pin／release／native 处理和失败回退；不把新增后台线程本身算作完成。
6. 根据剩余热点评估地址映射／卡表及对象头压缩，统计对象、对齐、side metadata 和临时计划的总成本。高成本候选先实验，收益不成立则记录后撤回，避免长期保留平行方案。

每阶段独立验证、提交和更新下一项瓶颈。完成通知修复不表示 GC 主线完成。

## 第一阶段：一次 epoch 确认与通知分流

普通 parker 和初始化等待者只在首次停稳或 epoch 变化时确认，通知独立的 collector 条件变量；mutator 条件变量只用于开始、恢复及初始化终态。去掉 `COLLECTING` 广播，保留 NativeSafe 无锁发布的有限超时复查。两个条件变量共用原 world lock，未改变根快照、对象／线程布局或 ABI。所有 profile 默认使用，重新链接 runtime 即可。

M3 Ultra ARM64，同一工具、系统库和源码，预热后五对 AB／BA；bintrees 深度 21，gcpause 为 200 万存活槽／3,000 万更新，threads 固定总共 640 棵深度 16 的树，refwrite 2 亿次写入。墙钟中位数（秒）：

| gcpause | 11.127 | 11.145 | +0.2% |
| threads 1／2 | 0.802／0.924 | 0.781／0.881 | −2.5%／−4.7% |
| threads 4／8／16 | 1.758／3.835／5.139 | 1.468／2.955／3.683 | −16.5%／−22.9%／−28.3% |

8／16 线程系统 CPU 从 17.19／47.38 s 降至 0.57／0.98 s，总 CPU 从 25.56／59.65 s 降至 7.21／10.78 s；五轮墙钟范围分别为 3.65～3.98 → 2.70～3.05 s、4.96～5.16 → 3.66～3.71 s。RSS 为 255.8 → 251.0 MiB、281.0 → 288.2 MiB；单线程、bintrees、gcpause 的 RSS 基本不变。调度变化会改变年轻对象寿命、晋升及 full 次数，不能声称两版 GC 工作量完全相同。小 gcpause 初测约 −6% 未在长负载重现，不计为收益。

验证：两机先 fmt／release clippy，各七项 C 驱动专测通过，覆盖 O0／O2、连续两轮 GC、无关唤醒、新线程、旧 parker 未恢复、NativeSafe、callback、初始化成功／失败及移动根。相同新回归在旧实现因重复确认失败。Darwin、GNU、musl 的线程／初始化正式专测各通过双 profile、共 14 个进程，含 ordinary、moving、minor；不重复全量 stress。86 个普通 runtime 对象均无测试钩子定义或引用。ARM64 threads 的 text 增加 120 B、文件增加 160 B；GNU 的代码／只读汇总增加 168 B，条件变量只增加一个进程级 native 对象。未修改编译器生产路径，首次冷构建与后续热重链接不用于推断编译速度变化。

剩余瓶颈：线程数增加仍降低固定工作量的吞吐；gcpause 晋升占分配约 87%，独立统计的 plan／copy／update 累计 1.97／1.63／3.02 s，普通 GC 仍为 STW。下一阶段实际实验高存活年轻块原地晋升、survivor 与容量组合，同时对照复制量、停顿、碎片和 RSS，再推进分配器与并发／增量阶段。

## 第二阶段：密集年轻块原地晋升

复用标记后的 block 存活统计，存活不少于可用容量一半的小对象块可原地晋升；稀疏块继续集中复制。保留块不预留目标、不建立逐对象计划／forwarding，收尾才改 generation 并回收死对象与空闲 line。source 选择直接返回是否存在源，没有源和 survivor 时跳过计划遍历，沿用既有零搬迁更新跳过路径。没有新增对象字段、根、TLAB 操作或 ABI。

**原地晋升以 `SCOOP_GC_PROMOTE_IN_PLACE=1` 开启，默认关闭；无源计划跳过默认启用。** 普通 debug／release 语义一致，moving／minor stress 和 full-only 保持原策略。现有 survivor 的同龄保留和第二轮晋升不依赖这个选项。理由是吞吐收益明确，但大存活集的 full 尾暂停与 RSS 回退尚未解决。

最终验证：两机先 fmt／release clippy，再各通过 16 项代际定向测试；覆盖 O0／O2、密集／稀疏混合、别名、原地晋升后的旧代写入、survivor、pin、callback、并发卡和块复用。预留失败测试改用真实稀疏源，开启原地晋升时仍触发 partial reservation 回滚并从原图转 full。Darwin、GNU、musl 各通过 nursery／复制正式专测，共 16 个 variants、36 次进程调用，含 debug／release、moving／minor、release hook 与大对象；没有全量 stress。

最终开关版本另做三轮对照：gcpause 关闭时复制／minor／full 与基线一致，开启时与 50% 候选一致；threads 开启 0.2166 s、候选 0.2163 s，refwrite 都为 0.0824 s。关闭时小 gcpause 0.993 → 1.016 s 的差异保留，没有宣称默认开关关闭也取得吞吐收益。ARM64 threads text 增加 208 B、配置字符串增加 67 B，四个完整文件大小均不变；86 个普通 runtime 对象均没有线程测试钩子。Scoop IR／布局与系统库可复用，仅重建 runtime 并重链接；没有增加逐次分配工作或编译器分析，首次 runtime 重建与热重链接的差异不作为编译加速结果。

## 第三阶段：线程本地块储备

普通 nursery 一次持 heap lock 最多准备四个 32 KiB block，首块作为 TLAB，其余三块由所属线程无锁切换。储备在锁内完成元数据初始化、年轻清单和容量登记；容量不足只取得剩余可用块，额外映射失败不否定已经取得的首块。GC、退出 managed 和 callback 返回同时使当前范围与储备失效；未用块由普通 minor 按空块回收。moving／minor stress 和 full-only 保持原逐块策略。普通 debug／release 默认启用，无新开关。

储备放入 mutator 已有对齐空隙，状态仍为 256 B、计数偏移仍为 128、generated prefix 仍为 56 B。每个活跃分配线程最多提前占用额外 96 KiB 年轻块容量及相应 side metadata，计入原 nursery 上限；不增加成功 bump 的指令、计数或 TLS 读取。提前取得容量会改变 GC 时机、晋升量与堆布局，不能把无锁切换简单换算成固定比例的总运行收益。

独立进度观测七对、四 GC worker、真实分配约 192 MB。四 mutator 的请求到停稳／STW／恢复到进度／应用间隔 p99 中位数分别为 24／290／48／357 → 23／280／34／331 μs，应用间隔 p95 317 → 302 μs，七轮最大间隔 2.242 → 2.235 ms。单 mutator 应用间隔 p99 162 → 165 μs、p95 106 → 126 μs、最大间隔 445 → 657 μs；不以多线程收益掩盖该短负载的尾部回退，进度间隔仍包括 1,024 次循环和调度。采样中大量线程在 GC 等待，不能把这些等待栈百分比当作 CPU 百分比；高线程数主要瓶颈继续是 collector 的 STW 工作。

两机先 fmt／release clippy，代际定向测试合计各 17 项通过，新增 O0／O2 覆盖容量、储备消费、部分映射失败、移动根、未用储备回收及 managed 退出。原块索引测试现在同时验证未用储备也属于真实年轻清单。三目标各通过线程分配与 native TLS／跨 Cone 回调／产物重链接，共四个 variants、24 次进程调用，含 ordinary／moving 和原 debug／release 组合。回调的旧指纹断言缺少与默认 debug 一致的 `--keep-symbols`，只修正该用例的链接设置后通过；没有扩大清理范围。

后续 region compaction 专测发现，四块储备使原交替分配输入的存活节点只分布在两个 region；其中一个作为目标，另一个被 pin 后已没有可搬迁源。该失败在阶段三固定 runtime 复现，阶段二不复现。测试现在于分配进入新 region 时退休当前 TLAB／储备，明确构造分散的节点，保留原搬迁、pin、释放和缩堆断言；ARM64 与 Linux x86_64 定向复测通过，没有改变生产搬迁策略。

ARM64 threads text 增加 176 B，GNU 代码／只读汇总增加 256 B；ARM64 四个程序文件大小均不变，ABI、系统库和编译器生产代码不变。86 个普通 runtime 对象均无线程测试钩子。本阶段降低了 refill 协调成本，但没有解决数倍的多线程和大存活集差距；下一阶段实际评估非搬迁 full 与旧代增量标记，继续减少单次 STW 的 mark／plan／update／reclaim 工作。

## 第四阶段：可选 full 分片标记

`SCOOP_GC_INCREMENTAL=1` 开启、默认关闭。旧代压力触发的 full 使用同一个 marker 和存活清单追踪两代，把标记拆成多个 STW 片；片间 worker 完全停止、mutator 继续运行。复用现有脏卡组记录已标记 owner 的改写，每片重新取得精确 roots，只为新 nursery block 补充计数索引。每个 worker 每片处理 1,024 个扫描单位，脏卡组计四个单位；这是任务粒度，不是暂停时间上界。成功 bump 不新增工作，只标记片保留有效 TLAB／储备。

队列排空或 nursery 满时，在同一 STW 内完成原 full 的 plan／copy／update／reclaim。片间不移动、不清扫，也不插入 minor；显式 full、预晋升／large 分配和真实分配失败取消未完成队列，再从完整原图执行原 full。pin 以最终片的实际状态决定搬迁资格，release 仍只在完整收尾执行。普通 debug／release 语义一致，stress／full-only 保持原完整收集。对象、生成屏障、根计划及 ABI 不变，系统库复用，runtime 重建后重链接即可。

同时修正显式 full 请求的完成语义：加入 minor 或未完成片后继续请求，加入请求开始后已完成的 full 可合并；不改变分配失败重试对“本线程实际完成 full”的判断。暂停直方图计每一片，full 次数只计完整周期，原测量消费者已同步。正常产物没有新增逐事件探针。

## 第十二阶段：旧代精确大小槽与按存活量触发 full

`SCOOP_GC_OLD_SLOTS=1` 开启，默认关闭。普通 minor 将 16～256 B 的晋升对象按精确大小放入旧代槽块，full 原地清扫后复用死亡槽；较大对象和预分配仍使用原路径。starts 是占用依据，槽游标留在 native block 记录中，不能放在可能被 VM discard 的死亡 payload。完整预留前不发布对象、forwarding 或 entry，失败恢复旧槽并释放新块。复用旧块中新对象的复制 marks 将其排除出旧卡回写，年轻存活清单独占这些槽。回写策略在扫描入口选择，关闭时复用原逐对象函数。
