# 循环范围指导数组访问内联

## 依据与设计

上一项数组边界检查优化在真实综合调用者中留下 `Array<Long>.get` 调用：优化报告记录增长成本 35、caller 剩余额度 24。循环的非负索引与同一数组长度关系已经成立，但内联器只代入常量和动态类型；因此保留不会执行的错误分支，也阻止后续无调用内层分块。

复用现有计数循环的稳定上界、支配、唯一加一与快照证明，将其用于本次调用点的实参与形参对应。先沿 callee 的真实条件选择完全可证明的标量数组路径，删除不可达分支，再用既有成本模型决定是否内联。保留实参求值和完整调用 ABI，不按方法名称识别，不消费更新过的 callee 模板，不提高阈值或返还已有增长额度。

未知条件、需要运行期 guard 的长度关系、取址、重赋、非单位步长或 callee 路径内的调用／EH 不取得该选择。只删除实际入选正文的不可达分支，不能把可能被后续优化的工作当作已经消除。单次选择期间按需复用同一 caller 的循环分析，普通不需要范围信息的内联不付出这项成本。

caller 分析按需建立一次，选择结束即释放；callee 的全部 local 先建立自身的未知状态，再按实参绑定事实，避免相同数值的 caller／callee local id 混用。调用结果写入使旧事实失效。数组身份只用于本次分析，输出正文仍使用 callee 自己的 typed 引用，并由既有内联器重分配身份。

## 定向验证

Rust 格式化、workspace Clippy、固定版本 Ruff 通过。本机 54 项 MIR 优化回归通过，覆盖共同估价、实参／局部副本、循环与重赋快照、原始 poll、递归和接口视图等本次涉及的公共路径。

Darwin ARM64、Linux GNU／musl 各通过两组正式 CLI 专测，每目标共 3 个 variant、12 次进程调用，没有运行完整验收：

- [数组范围内联](../../tests/fixtures/compiler-correctness/optimization/lowering/array-inlining/fixture.toml)：在多个数组、分支和反复遍历的真实调用者中，核对 getter 消失、实际保留正文的成本下降及新增分块。debug 保持原形；运行覆盖 1、63、64、65、129、1025 个元素、零次循环、更新前的索引快照、更新后的越界索引、较短目标数组和改变上界后的异常前缀。
- [范围内联与并发 GC](../../tests/fixtures/gc-correctness/poll/array-inlining/fixture.toml)：复用同一组 kernel，两个 callback mutator 各执行 64 轮 2049／2050 元素数组求和，同时请求收集。moving／minor 均通过，报告与 MIR 确认受测调用者实际命中新优化；保留 100 µs NativeSafe 收集请求间隔。

初次 CLI 载体遗漏了 Cone 的 package 声明，补齐后两组专测通过；该批配置失败不计为通过。未修改 runtime 或产物格式，也未重复无关的全量验证。

## 真实产物与运行测量

基线为 `2b4e2845d`。复用不变的 [数组基准](../../tests/benchmarks/arrays/counted.scoop)、[phase companion](../../tests/benchmarks/interfaces/phases.c) 与 [A/B 入口](../../tests/benchmarks/compare.py)。双方使用普通 release、同一预编译 sysroot、生产 runtime 和一个 GC worker；GC 统计另跑。Darwin 为 M3 Ultra／LLVM 22.1.8，GNU／musl 为 nuc12 i7-12700H／LLVM 22.1.2，使用基础目标，不采用 `-march=native`。

三个目标的报告都显示：原 getter 参数化后的 size 为 41，增长为 35，超过 caller 剩余 24；范围化简后实际 size／execution 为 6，增长为 1，因此在不增加额度的条件下内联。需要等待前置普通化简暴露循环结构时，报告仍保留早先的拒绝事件，随后记录实际接受；没有改动三轮上限或稳定模板策略。

综合调用者 `exercise` 的完整块由 5 增至 6，新增求和；原有三个长度 guard 和八个 LIR poll 位置保持。真实反汇编确认求和内层只有标量元素加载、累加与倒计数，没有 getter 调用、逐元素 bounds check 或新增内层 poll。独立 sum／transform／copy／reduction 的 LIR 均保持，不能将这些对照的时间变化当作新算法收益。

每模式一对预热、七对交替 AB／BA，双方输出一致。大数组为 65536 元素、128 次遍历；单元素模式为 100000 次遍历。分配与初始化位于 phase 外，结果在 phase 后输出。以下为同机独立样本中位数，不是显著性判断或跨语言排名。

## 空间、编译成本与默认策略

| 目标 | 根 Cone `.slib` bytes | 完整程序 text bytes | 完整程序文件 bytes |
| --- | --- | --- | --- |
| Darwin ARM64 | 705580 → 705070（−510） | 1018952 → 1018976（+24） | 18021224 → 18020872（−352） |
| Linux GNU | 869924 → 868406（−1518） | 1152913 → 1152913 | 17582552 → 17582256（−296） |
| Linux musl | 868380 → 867048（−1332） | 1222526 → 1222590（+64） | 16978600 → 16978304（−296） |

每目标的 64 条 TD／接口表／布局记录逐字相同。11 种负载的分配、nursery 分配、minor／full 次数、晋升、复制和 root slots 统计相同；这些普通运行未触发 GC，移动正确性由上述专测覆盖。接口表示、runtime／metadata／`.slib` ABI 与优化报告 schema 保持，不增加持久字段或额外 roots。

关闭观察输出，只编译根 Cone、消费预编译依赖；一对预热和五对正式 AB／BA。编译墙钟中位数 Darwin 1.0457 → 1.0346 s（−1.07%），GNU 1.4944 → 1.5140 s（+1.32%），musl 1.4984 → 1.5135 s（+1.01%）；CPU 时间变化 −1.00%／+1.10%／+1.12%，峰值 RSS 变化 +3.19%／−0.04%／+0.07%。保留 Darwin 约 19 MB 的编译峰值增量，负时间差不外推为普遍编译加速。

本项沿用 release 默认内联：只为已拒绝且确有数组操作的循环内调用建立范围分析，真正删除的分支才降低成本，目标路径在三平台均有收益，运行期与静态成本小。未知长度关系、复杂控制流、浮点／引用元素、未展开的容器访问和更广的跨过程证明继续按实际需求推进；代码布局与短任务测量归因也仍待改进。本项不引入新的开关、优化等级或 PGO。

原始产物、日志、反汇编、逐次 JSON 与脚本保留在两机忽略的 `tmp/program-performance/array-inlining`，文档只记录结论和必要限制。
