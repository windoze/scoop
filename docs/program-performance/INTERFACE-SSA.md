# 接口复制、根恢复与 SSA

本批基线为 `a6d91f9e4`。按三个阶段分别实现局部复制传播、调用期间保活与返回恢复的区分、接口分量及重定位结果的 SSA。复用同一 core／runtime，不改变两字接口布局、itab 投影和跨 Cone ABI。

## 第一阶段：局部复制传播

release 在 MIR 内联、字符串融合和有界循环选择之后运行末尾清理，复用现有 CFG 数据流，传播所有未取址局部的当前复制事实。重赋撤销指向被改写源的别名，旧副本自身保留；合流取共同事实，循环按原固定点计算。消除不再读取的纯复制，不合并可变槽，不按局部名称识别。没有新增开关或运行时诊断代码。

初次把当前复制事实直接用于全部分析，会同时改变调用点内联选择，ARM64 lambdas 回退约 22%；该候选未采纳。最终末尾清理保持前序策略，lambdas 的最内层 List 迭代保持 23 条指令／15 条栈访存，耗时仍回退 6.27%，留作后续阶段的明确对照。原先按顺序地址区间得到的 431／204→392／162 包含冷路径，已在第三阶段按真实 CFG 回边纠正，不作为循环优化证据。

Darwin M3 Ultra（LLVM 22.1.8）和 nuc12 i7-12700H（LLVM 22.1.2，GNU／musl）实机各预热一对、五对交替测量。没有固定 CPU affinity；进程时间含启动与输出，不作周期或单次 forwarding 成本推断。用户原 dispatch／dispatch_class／lambdas 源保持不变，新增三个数据流负载见 benchmarks/interfaces/ssa。各对输出一致，dispatch 保持 `66854100000000`。

| dispatch | 0.852912→0.671455 | 0.489730→0.478387 | 0.497061→0.489576 |

ARM64 dispatch 热循环栈访存指令 37→29，poll 快路径 31→23，消除四组中间复制；stp／ldp 各计一条，不是逐字访问数。GNU／musl 同一循环 32→31，快路径 24→23，此前已有局部接口快照复用。List<Long> 的内层指令完全保持，GNU 此次 +5.45% 仍保留在结果中；整体布局和采样波动未拆清。父投影继续固定 itab 偏移，不增加目录查询。

六程序完整文件大小全部不变。ARM64 text 变化 −96～+100 B；GNU／musl 只有 lambdas 减少 384 B，其余对齐后不变。三次独立冷 consumer 构建（含链接）中位数 ARM64 2.980→2.723 s、GNU 3.597→3.408 s、musl 3.590→3.383 s；CPU 时间分别 −0.82%、−5.41%、−5.83%，峰值 RSS 变化均不足 0.7%。这些不是交替编译样本，只用于排除明显成本增长，不宣称编译加速。

两机先格式化和相关 Clippy，再通过 71 项 MIR 优化测试；各目标均通过 `interface-ssa` 的 debug／release 四次进程调用，release 使用 moving／minor stress。覆盖循环定义、复制链、重赋快照、取址、合流、异常出口、接口返回、数组副本与父投影。没有跑完整验收。

原始日志、IR、机器码及逐次样本在两机仓库外 `scoop-performance-results/2026-10-26/interface-ssa`，最终第一阶段计时为 `baseline-copies-late`；`early-copies` 是未采纳的前序分析试验。必要存储和全量恢复仍由后续两阶段继续精化，本阶段没有删除 volatile 或改变重定位契约。

## 第二阶段：区分保活与恢复

LIR 的普通 Managed call 根来源新增恢复需求：直接 AS1 实参仍在调用期间保活，正常返回后已死时不生成恢复 `llvm.fake.use`、reload 或写回。正常后继活跃值、Indirect／byval storage、分配展开后继续使用的输入和 poll 根保留恢复；invoke 的正常／异常显式根、native borrow／发布协议保持。最终逻辑身份只要求需要恢复的来源，物理根仍消费 RS4GC 结果，不改变 stackmap、`.slib` 或外部 ABI。全部 profile 默认采用，没有运行时诊断代码。

debug 增加已有的普通 EarlyCSE，合并无中间写入的重复普通加载。实际 moving 用例发现，不这样做会让实参与恢复值直到机器下降才合并，引起既有精确 root 数检查不一致；修复没有放宽检查或增加独立根等价分析。

## 第三阶段：接口分量与重定位结果的 SSA

release 只将未逃逸入口栈槽上的编译器 GC 专用读取／恢复写入转为普通访存，复用 SROA／mem2reg 和现有标量优化；真实取址、根发布、Indirect／byval、native／EH 及未知地址用途保留存储。用户 volatile／atomic 和 TLAB 取址位置约束不变。没有按类型或变量名合并可变槽，没有改变两字接口表示。

所有普通 LLVM 优化与 helper 内联结束后、根定稿和 RS4GC 之前，沿实际 aggregate 定义拆出 managed leaf 与其余分量。PHI／select 和循环回边分别合流，invoke 的正常边复用现有拆边工具；真实返回、存储和继续传参在使用点重建。之后不再运行会把重建折回旧 aggregate 的普通优化，RS4GC 因而改写实际业务使用。晚期分解适用于全部 profile；存储提升作为 release 默认，无新开关、runtime 代码或产物格式变更。

最小 LLVM 反例在修复前触发 safepoint verifier，修复后在三个目标、两个 profile 下直接断言 ret／store／后续实参的 object 是 relocate 结果，而非仅检查其存在。另覆盖接口结果 PHI、select／None、循环回边、条件 poll、共享正常出口的 invoke、landingpad，以及未逃逸／发布／用户 volatile 三类存储。动态索引的局部数组不能提升时，回归直接检查最终两个 leaf 写回都使用 relocate 结果，再从存储读取返回值。两机各 50 项 statepoint 与 18 项 moving 后端测试通过；三个目标的 interface-ssa、conditional-interface-roots、reference-array-roots 合计各四个变体、15 次进程调用通过，没有完整验收。包含快照重赋、可空接口、嵌套值、装箱、父投影、数组卡标记、native callback、正常／异常返回及并发收集；新增 fixture 的 debug／release 均启用 moving stress。单独诊断确认三平台各实际复制 9,448 B，不用计时阈值判定正确性。

按支配关系确认自然循环回边，选择含间接调用的最内层循环，统计其实际块中的栈访存；括号为 poll 快路径。stp／ldp 仍各计一条，既不是逐字访存次数，也不是周期模型：

| --- | ---: | ---: |
| dispatch | 37→4（31→2） | 32→5（24→3） |
| dispatch_class | 21→4（15→2） | 23→5（15→3） |
| lambdas 的 List 迭代 | 15→4（9→2） | 19→9（11→5） |
| List<Long> | 15→4（9→2） | 19→8（11→4） |

dispatch 的 object 从数组直接进入 receiver，原七组局部槽复制消失；返回后死 receiver 不再重载，活跃容器仍 spill／恢复。class 对照在调用后仍读取 receiver 字段，保留真正需要的 receiver 重定位。接口数组保留实际 heap 写入、卡标记与父表指针调整；itab 不进 GC roots。lambdas／数组的旧顺序区间脚本会误选冷代码回跳，原始输出保留，最终使用仓库外 `inspect_loops.py` 及 `loop-summary.json`；dispatch 计数不受此修正影响。

第三阶段六程序 text 减少 ARM64 148～700 B、GNU／musl 192～960 B；相对本批基线累计减少 184～932 B、256～1,664 B。完整文件 ARM64 均不变，GNU dispatch 减少 4,096 B，musl List<Long> 与接口数组各减少 4,096 B，其余不变。无静态接口表膨胀。

第三阶段三次冷 consumer 编译（含链接）墙钟中位数 ARM64 2.826→2.792 s、GNU 3.415→3.424 s、musl 3.395→3.403 s；CPU 时间变化 +0.22%、−0.06%、+0.20%，峰值 RSS 变化 −1.76%、+0.05%、−0.10%。成本没有明显增长；独立冷构建的小差异不作统计显著性或编译加速结论。原始计时在 `roots-ssa` 和 `baseline-ssa`，ARM64 与 x86_64 均为实机结果。

保留限制：debug 可以继续保留局部存储；真实取址／发布、间接 ABI、native borrow、EH 和保守未知地址路径仍需 canonical storage／重读。调用期间必要的机器根 spill、后续仍活跃引用的恢复、poll 和写屏障继续存在。编译器没有承诺所有引用零落栈；跨 safepoint 的内部裸地址也不能由此次 SSA 变换获得额外有效期。
