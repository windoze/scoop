# 接口复制、根恢复与 SSA

本批基线为 `a6d91f9e4`。按三个阶段分别实现局部复制传播、调用期间保活与返回恢复的区分、接口分量及重定位结果的 SSA。复用同一 core／runtime，不改变两字接口布局、itab 投影和跨 Cone ABI。

## 第一阶段：局部复制传播

release 在 MIR 内联、字符串融合和有界循环选择之后运行末尾清理，复用现有 CFG 数据流，传播所有未取址局部的当前复制事实。重赋撤销指向被改写源的别名，旧副本自身保留；合流取共同事实，循环按原固定点计算。消除不再读取的纯复制，不合并可变槽，不按局部名称识别。没有新增开关或运行时诊断代码。

初次把当前复制事实直接用于全部分析，会同时改变调用点内联选择，ARM64 lambdas 回退约 22%；该候选未采纳。最终末尾清理保持前序策略，lambdas 循环由 431 条指令／204 条栈访存降至 392／162，耗时仍回退 6.27%，留作后续阶段的明确对照。更少的指令不直接等同于更快。

Darwin M3 Ultra（LLVM 22.1.8）和 nuc12 i7-12700H（LLVM 22.1.2，GNU／musl）实机各预热一对、五对交替测量。没有固定 CPU affinity；进程时间含启动与输出，不作周期或单次 forwarding 成本推断。用户原 dispatch／dispatch_class／lambdas 源保持不变，新增三个数据流负载见 benchmarks/interfaces/ssa。各对输出一致，dispatch 保持 `66854100000000`。

ARM64 dispatch 热循环栈访存指令 37→29，poll 快路径 31→23，消除四组中间复制；stp／ldp 各计一条，不是逐字访问数。GNU／musl 同一循环 32→31，快路径 24→23，此前已有局部接口快照复用。List<Long> 的内层指令完全保持，GNU 此次 +5.45% 仍保留在结果中；整体布局和采样波动未拆清。父投影继续固定 itab 偏移，不增加目录查询。

六程序完整文件大小全部不变。ARM64 text 变化 −96～+100 B；GNU／musl 只有 lambdas 减少 384 B，其余对齐后不变。三次独立冷 consumer 构建（含链接）中位数 ARM64 2.980→2.723 s、GNU 3.597→3.408 s、musl 3.590→3.383 s；CPU 时间分别 −0.82%、−5.41%、−5.83%，峰值 RSS 变化均不足 0.7%。这些不是交替编译样本，只用于排除明显成本增长，不宣称编译加速。

两机先格式化和相关 Clippy，再通过 71 项 MIR 优化测试；各目标均通过 `interface-ssa` 的 debug／release 四次进程调用，release 使用 moving／minor stress。覆盖循环定义、复制链、重赋快照、取址、合流、异常出口、接口返回、数组副本与父投影。没有跑完整验收。

原始日志、IR、机器码及逐次样本在两机仓库外 `scoop-performance-results/2026-10-26/interface-ssa`，最终第一阶段计时为 `baseline-copies-late`；`early-copies` 是未采纳的前序分析试验。必要存储和全量恢复仍由后续两阶段继续精化，本阶段没有删除 volatile 或改变重定位契约。
