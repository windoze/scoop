# String 比较与有界 hash

基线为 `20050b507`；两边分别用对应编译器构建同一版本 core，候选只改变本项正文，runtime 完全相同。String.equals 的同引用、长度不等及空串判断是普通 core 正文，剩余比较使用原 typed compare；hash 对至多八字节展开原 FNV-1a，较长输入共享 C 后备。正文由现有调用点评分选择，未增加函数名特判或内联门槛。

MIR 常量事实新增真实 StringConstId，复用数据流及调用点简化；真实 typed byteLength、合法 byteAt 和 compare 可计算为常量。实际 provider 身份保持，文本相等不推导对象同一。release codegen 对本地已知 ≤8 B 常量比较生成长度保护与无符号字节序比较；空串只需检查长度，其他长度及未知内容继续调用共享 compare。只读实际范围，保持 NUL、Unicode、hash 回绕和原 ABI。单侧 imported immortal 若 LIR 只有地址则不假设其内容；双侧已知内容可在 MIR 折叠。

两机格式化／Clippy 通过。三目标各 2 项 core 测试及 2 profile、6 次进程的优化 fixture 通过：0～9 B、NUL／高字节／多字节 hash 的固定旧结果、接口调用、同引用与复制、Unicode 字典序及 moving／minor stress。MIR 确认常量长度、比较和 hash 消除调用；机器码确认短常量分支直接读取、常量 hash 无调用，动态 hash 仍可复用已优化的 core callable。所有 profile 使用相同布局和库声明。

长 hash 多一次长度分支，实测增加约 0.3%～1.1%；不把扫描正文复制到每个调用点。比较／hash 不分配；十万次各模式总分配旧新相同：480／480／496／496／496／3,200,488／3,200,488 B，包含输入、输出和遍历的真实 iterator。既有分配优化未重复计入本项。

ASCII 单独生成曾作独立候选：GNU／musl 的 ASCII 遍历减少约 30%，但混合 Unicode 最差增加约 5.7%；ARM64 没有稳定收益。该展开已撤回，完整 1～4 B 解码仍使用已有 NoGC leaf。最终 ARM64 的未修改 ASCII 遍历仍增加约 27.4%，Unicode 增加约 2.8%；对应解码与遍历指令保持、地址与链接布局改变。此对照含接口 iterator 调用、分配及布局影响，不能将整个差值归因于解码算法；保留此回退，下一接口 SSA 批次继续使用相同程序对照。Linux 相应小幅变化也不计作本项优化收益。

最终 text 减少 356／576／576 B，完整文件减少 3,152／3,448／3,448 B；core.slib 减少 54,850／91,700／103,344 B。三对独立冷 consumer 编译墙钟变化 −0.63%／+0.05%／−3.32%，CPU −1.11%／−0.22%／−3.27%，峰值 RSS +1.51%／+0.28%／+0.25%。无新测量代码、runtime ABI、`.slib` 格式或公开开关；上述有界比较和普通正文作为 release 默认能力，UTF-8 展开未采纳。
