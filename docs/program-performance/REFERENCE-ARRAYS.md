# 引用数组的范围证明与有界循环

本项把既有范围证明和 64 次有界内层用于引用元素，覆盖字段读取、身份搜索、复制、条件初始化及合法 wrapper 存储。沿用实现规范 2.19 与运行时规范 3.2／3.6，普通数组、部分初始化、异常与 GC 语义保持。

## 选择范围与实现

继续复用当前计数循环的归纳变量、稳定长度、单入口／单 latch、条件合流和共享提前退出分析。正文值可以是 class／数组／Any／String／函数引用、完整双字 interface，以及复用这些或标量表示的 `MaybeUninit`。两支 enum 仅在一支为空、另一支只有一个引用字段时参与；依据实际字段与 intrinsic representation 识别，覆盖可空引用，也覆盖普通等形 enum，不按类型名字特判。

引用读取、普通字段读取、身份比较、typed variant 构造／测试／投影和 wrapper 操作可进入内层。只有无需 runtime 目录查询的引用转换可进入：单字重定型、提取 interface object、空接口、final class 静态取表、exact Child 到 Parent 的表投影。已存在的泛型父表布局由 LIR 使用；MIR 只沿当前父接口关系判断该转换能否成为普通固定操作。

真实 `ChildToken<Long>` 继承 `Marker` 与 `Token<Long>`，其数组投影使用完整 `{ object, itab }` 值，Parent 视图的 itab 在本用例中加 8 字节。元素可以是 class 或装箱 struct，后续通过 Parent 调用都保留对应具体实现。该路径延续[完整父表投影](INTERFACE-PROJECTION.md)，不会扫描对象 TD。开放类的动态取表、Any 首次动态视图和无静态关系的检查继续按原语义处理。

范围证明同时服务已展开正文与既有数组内联选择；不改变内联阈值。已证明的检查消失，其他数组用长度 guard 选择完整块，短尾或不满足 guard 时继续执行原 checked 路径。引用搜索首次命中后直接退出，共享本轮 typed 值。

原入口及循环 header 的 poll 保留，内层最多 64 次。ArraySet 的屏障仍在实际写入后完成，未删除、延迟或批量合并；`MaybeUninit.uninit()` 保留合法的空引用存储。roots 来自最终实际使用，每个 poll 后恢复当前对象引用，不新增备用 roots 或跨 safepoint 的裸地址／card metadata。LLVM 的显式向量化资格保持原限制，引用内层使用标量操作。

## 定向验证

- 本机和 Linux 各通过 58 项 MIR 优化回归；Rust 格式、workspace Clippy 及固定版本 Ruff 通过。
- Darwin ARM64、Linux GNU／musl 各通过新引用数组优化／GC 两组及既有数组内核回归，共 5 个变体、19 次进程调用。覆盖 debug／release、0／1／63／64／65／129／1025、同数组别名、首次／未命中、短目标的已写前缀和提前退出、普通等形 enum、可空 interface、MaybeUninit、String、闭包、Any 装箱、泛型非零父表偏移和空接口。开放类取表、未知方法分派、一般多引用聚合及逐元素对象分配保留原路径。
- GC 用例先使目标存储成为旧对象，再由独立函数创建并写入年轻值。函数返回后才触发真实 minor GC；实际 LIR 中，该调用点只保留数组等原有根，没有年轻元素的额外局部根。Node／interface／可空 interface／wrapper 分别覆盖多个 card 和 64 KiB 边界，避免其他根掩盖缺失屏障。清零后继续保留数组，确认活对象数下降，验证元素引用确实释放。两条 mutator 与间隔发起收集的 collector 继续覆盖 moving／minor，以及退出返回的引用、捕获对象的闭包和接口调用。
- MIR、LIR 与三目标机器码确认 13 个主要内核形成完整块，完整块内没有 poll、分配或接口目录查询；Child 到第二个 Parent 只作固定偏移，引用存储的卡标记指令保持。16 个被检查函数的 poll 身份和 live 集合相同；部分函数因冷异常调用消失而改变私有 call-target 索引，该索引变化不属于根集合变化。
- 235 条 TD／接口表／类型布局记录完全一致。22 种负载的分配字节、nursery 字节、minor／full 次数、晋升／复制字节、root slots、dirty cards、old reference slots 和 traced objects 相同。NoGC 对照 LIR 相同。

新载体的 lambda 写法、入口 poll 计数及 `gcStats` 的对象数单位期望已修正。定向回归还发现 `writePrefix` 的旧负向断言：在本项基线中已生成长度 guard 与完整块，修正其期望后通过；逐元素分配对象的负向断言保持。补强清零回收断言后仅重跑受影响的 GC 组，未运行完整 workspace tests 或全量 CLI fixture。

## 运行性能

以 `1a9d82be7` 与本项工具编译相同[基准 Cone](../../tests/benchmarks/arrays/references)，使用同一预编译 sysroot。每模式预热一对后测五对 AB／BA，GC 诊断另跑，Linux 固定 CPU 4。长数组为 65,536 元素、128 轮；短数组和首项命中为 10 万轮。输入、目标存储在阶段计时前准备，只有初始化模式将所测数组的分配计入阶段。Node 字段读取遍历不同对象。

身份搜索已内联进 `exercise`；其实际执行路径还消除了基线中保留的一个 getter 调用，不能把约 95% 的降低全部归因于分块。字段／可空读取与复制等其余核心函数仍被实际调用，初始化部分的内联副本同样检查。首项命中阶段降低 61.68%／77.63%／77.72%，包含相同的内联收益。

三类读取／搜索的整进程耗时降低 2.49%～74.84%。Darwin 各写入模式降低 9.14%～23.79%；GNU／musl 写入总体接近持平，保留阶段 +0.24%／+0.25% 和整进程最大 +0.12% 的小幅回退。x86 生成代码仍逐元素执行原子的 card 标记，后续重复标记消除或 bulk barrier 应以这些真实内核测量，而不是推定当前分块会消除屏障成本。

六个单元素模式的阶段变化为 −0.42%～+6.35%，最大绝对回退约 0.686 ns／次，整进程最大 +2.23%。标量求和对照阶段变化 −2.09%／−1.97%／−0.93%，NoGC 对照 +0.36%／−0.04%／−0.09%；整进程会同时受计时前引用数组准备的改变影响，不能把它等同于对照内核自身变化。

编译成本为无 dump 的根 Cone 编译，消费相同 core，独立输出，预热一对后五对 AB／BA，不包含最终链接。完整文件包含代码、异常／GC 元数据及目标格式对齐；不能把文件总增量全算作方法代码。接口值、对象、静态派发表及 `.slib`／runtime ABI 不变。

该有限能力复用已有分析，编译与空间成本较低，作为 release 默认能力。读取／搜索在三目标获益，带屏障写入的目标差异和短路径成本单独保留。本项未增加优化等级，也未引入批量屏障或引用 SIMD。一般聚合、动态取表、未知调用、EH、多回边、嵌套循环及更广索引关系继续独立推进；不据此宣称已达到跨语言综合性能目标。
