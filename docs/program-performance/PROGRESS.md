# 程序性能优化实施记录

本轮从 `de5f4609b` 开始，工作分支为 `codex/program-performance`。范围与取舍以[调研报告](INVESTIGATION.md)为依据：测量能力提前独立交付，持续改进编译器、runtime 与库；PGO 后续按实际消费者和收益安排。

各项已采纳方案的开启方式与适用条件统一见[简略清单](ENABLED-OPTIMIZATIONS.md)，后续交付与默认策略调整时同步更新。

- 已完成 [String 比较与短 hash](STRING-READS.md)：ordinary core 处理身份／长度与有界 FNV-1a，复用调用点常量事实；真实 typed 短常量比较生成有边界保护的读取。三目标定向语义、两 profile 的 IR／moving 与成本对照通过；ASCII 单独展开因混合 Unicode 回退未采纳。后续优先推进接口复制、根恢复与 SSA 重定位；字符串复制／Char 编码、初始化就绪与 Context 测量仍在 runtime 可见化的后续批次。

## 交付约定

- 每项功能完成必要验证后单独提交、推送，再获取并合并 `origin/main` 的更新。实验实现留在本地或临时实验分支，只有形成可交付结论的实现进入推送分支。
- 成本低且收益稳定的优化进入 release 默认设置；高成本或收益不稳定的方案通过实际需要的开关或等级提供，保留默认 release 对照。
- 诊断／测量专用的生成代码必须由明确的编译期开关控制；关闭时不得出现在最终产物中，不能只在运行时禁用。
- 临时源码和构建放本仓库忽略的 `tmp/program-performance`，后续原始日志和逐次测量数据放在仓库外 `scoop-performance-results`；定期检查并清理已无用途的 target 产物，保留仍需复用的构建缓存。
- 每项改动只运行一组足以证实其正确性的定向验证；先完成本机验证，涉及平台合同再在 `nuc12:~/repos/scoop` 补相应 Linux 组合，不默认运行完整验收。只有新增失败或合并影响要求时才扩大范围。
