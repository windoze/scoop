# 有界引用循环的卡标记合并

以 `90b6d676d` 为基线，接续页表查询提升与接口值复用。本项在三个现有目标的 release 默认启用，没有新增公开开关或等级。接口父表投影、对象表示和全部 profile 的 ABI 保持。

## 设计与适用条件

GC 只在所有 mutator 停稳后扫描和清零二值 card。已有 64 次有界内层没有 safepoint，因而可以在完成整块写入后、下一个 poll 或发布之前，一次完成对应的卡标记。

先修订运行时规范 3.6 和实现规范 2.5／2.19，再复用实际 LLVM CFG 的单入口、单 latch、无内部循环和唯一正常出口分析。迭代次数须为 2～64 的已知常数；每组被合并的写入必须每轮必经，mapping prefix 已在循环外取得。按实际 64-bit SSA、固定更新的 header phi、加减、常数缩放和 GEP 确认引用槽步长为 0、8 或 16 字节。变化目标、未知增量、不能保持增量的截断／扩展、条件写入、调用、同步、发布和提前退出继续保留原标记。

在 latch 的正常退出边插入一个块，修正原后继 phi 的 incoming block，保留其值。由最后一次实际槽偏移减去 `(次数 − 1) × 步长` 得到首槽偏移，标记起止和中间实际触及的卡。每个写入流最多三个 relaxed atomic store；允许重复标记同一端点，但不标脏未触及的卡。多个合格写入流共用退出块，未合格的流仍逐次标记。

全部元素写入和 volatile 引用重读保留原位置与顺序；仅把专用于最终卡计算的纯地址运算移到退出边，不额外提升普通根加载。页表 prefix 和地址不跨 safepoint，不增加根、MIR／LIR／`.slib` 字段、runtime ABI 或引用 SIMD 资格。ARM64 沿用已交付的栈重取规则，x86 仍排除含 volatile 的区域；因此 x86 的接口合流初始化目前仍可能保留逐次查询和标记。

## 必要验证

- 两机均通过格式化、workspace Clippy 和 14 项有界循环后端专测。新增用例覆盖 0／8／16 字节步长、2／64 次、多写入流、条件 CFG、进入 guard 与退出 phi，以及不合格地址、调用、原子发布和根重赋；三目标 LLVM safepoint verifier、精确根及真实对象发射通过。
- Darwin ARM64、Linux GNU／musl 各通过 [reference-array-roots](../../tests/fixtures/gc-correctness/poll/reference-arrays/fixture.toml) 和 [runtime-cards-moving](../../tests/fixtures/gc-correctness/codegen/runtime/cards-moving.fixture.toml)，每目标五个变体、11 次成功进程调用。包括跨 card／64 KiB 的旧数组唯一持有年轻 Node、interface、可空 interface 和 wrapper，清零后的回收，以及并发 moving／minor、字段与原子发布。没有全量验收或重建未变化的系统库。
- 三目标 16 种运行模式输出一致；完整 LIR、235 条 TD／接口表／布局记录、16 个函数的 poll／live 集合保持。22 种负载的 15 项分配、GC、脏卡与扫描计数相同，未因合并额外增加脏卡或延长对象存活。

收尾审查补入外层 phi 提供卡偏移的回归，捕获了退出边重建 phi 后继续持有旧 LLVM 句柄、误用 32-bit 值的问题。改为分割后读取当前操作数，回归先失败后通过；未提交或推送有缺陷的候选。最终两机 14 项测试通过，三个目标的根 `.slib` 与已测候选逐字节相同，因此复用原运行／GC 数据；编译成本用最终编译器重测。

真实机器码中，每 64 次的单字复制由 64 次卡写入改为退出后的 2 次；双字接口复制／父投影为 3 次。ARM64 普通复制内层 11→9 条指令，接口复制 20→18，父投影 22→20；x86 分别为 10→8、10→8、13→11。清零内层为 ARM64 7→5、x86 8→5。内层不再标卡，原短尾和不合格循环仍保留原屏障；已有静态父接口投影继续不查接口目录。

## 运行结果

双方编译相同[引用数组基准](../../tests/benchmarks/arrays/references)，消费同一预编译 core 和 runtime。M3 Ultra／LLVM 22.1.8 与 nuc12 i7-12700H／LLVM 22.1.2；Linux 固定 CPU 4。长数组为 65,536 元素、128 轮，短模式及首项命中为 10 万轮。一对预热后五对 AB／BA，GC 统计单独测量；必要复测为两对预热、九对 AB／BA。下表为首轮内核墙钟中位数变化，负数表示降低。

| 操作 | Darwin ARM64 | Linux GNU | Linux musl |
| --- | ---: | ---: | ---: |
| Node 复制 | −26.45% | −55.11% | −47.89% |
| interface 复制 | −4.42% | −46.10% | −46.81% |
| Child 数组投影到 Parent | −2.49% | −43.16% | −44.02% |
| String 复制 | −28.49% | −48.44% | −53.00% |
| 闭包引用复制 | −27.26% | −44.15% | −52.82% |
| 可空引用复制 | −26.59% | −53.96% | −68.70% |
| wrapper 清零 | −79.33% | −44.69% | −63.10% |
| Node 分配与初始化 | −16.11% | +2.43% | −2.18% |
| wrapper 分配与初始化 | −17.88% | −2.48% | −3.66% |
| interface 分配与初始化 | −6.82% | +1.67% | −1.06% |

普通引用复制的整进程耗时降低 ARM64 2.90%～6.09%、GNU 10.64%～14.35%、musl 8.29%～15.49%。GNU／musl 接口复制及父投影整进程降低 10.96%～16.49%。ARM64 接口复制／父投影九对复测为 −6.41%／−2.90%，整进程为 −2.42%／−1.18%。

保留以下回退和限制：

- ARM64 字段求和首轮 +13.06%，复测 +8.42%（整进程 +0.74%）；其独立函数指令、两个六指令内层和模 32 对齐相同，函数位置移动 160 B。样本波动与布局影响未完全拆清，不能据其他模式的收益推断此回退已解决。
- GNU Node／interface 含分配初始化复测为 +2.13%／+2.33%（整进程 +2.08%／+1.82%）。Node 内层已合并；interface 初始化仍保留原路径，268 条指令除重定位外相同。这里保留实际代价，不把初始化一概列为获益。
- GNU 单元素接口复制首轮 +9.18%（约 +0.807 ns／次），复测 −0.95%；ARM64 首项命中 +13.47% 降至复测 +2.46%（约 +0.060 ns／次）。其余短模式最大绝对回退约为 ARM64 0.25、GNU 0.327、musl 0.505 ns／次。未改变路径的小幅负差不作为本项收益。

## 编译与空间成本

| 变化 | Darwin ARM64 | Linux GNU | Linux musl |
| --- | ---: | ---: | ---: |
| text | +276 B | +320 B | +320 B |
| 完整程序文件 | 0 B | 0 B | 0 B |
| 根 Cone `.slib` | +320 B | +288 B | +288 B |
| 编译墙钟 | −0.45% | −0.12% | +0.06% |
| 编译 CPU | −0.78% | −0.14% | +0.14% |
| 编译峰值 RSS | +0.93% | +0.16% | +0.15% |

text 增长约 0.032%～0.035%，根 `.slib` 增长约 0.008%～0.011%，静态类型与接口表不增长。编译测量仅构建根 Cone，消费同一预编译 core，关闭 dump，一对预热后五对 AB／BA，不含链接；不把小幅负差解释为编译加速。初次编译墙钟为 +1.16%／−0.07%／−2.37%，旧样本保留，表中采用最终编译器的 `final-compilation` 结果。

合格引用复制与清零收益稳定，空间及编译成本较小，因此采用 release 默认策略。更广的条件写入、跨块同卡合并、young 初始化屏障消除和 bulk barrier 仍须独立测量。原始日志、产物与样本位于两机忽略的 `tmp/program-performance/card-batches`；[简略开启条件清单](ENABLED-OPTIMIZATIONS.md)同步维护。
