# 确定初始化前的尾部清零消除

当前规则已在 [GC 第三十一阶段](GC-EVOLUTION.md#第三十一阶段引用字段的确定初始化) 扩展到直接引用、接口、null niche enum 与无 padding 的引用聚合；全部省略字节必须在下一次可能 GC、观察或发布之前由原 typed store 完整初始化。目标大小门槛及慢路径保持，当前 ABI 为 25。本页以下保留 2026-10-25 的无引用版本与当时的独立测量，不代表当前 GC 配置。

2026-10-25，在 `13a769a3b` 的分配路径上消除被构造写入立即覆盖的零写入。作为 **release 默认能力**，适用于已有小型 TLAB 内联条件，且对齐后大小在 ARM64 不超过 128 B、x86 不超过 64 B 的普通对象；没有新增公开开关或等级，条件同步到[简略清单](ENABLED-OPTIMIZATIONS.md)。

codegen 从分配结果沿无条件控制流跟踪未取址的局部副本，记录对同一新对象的 typed 字段存储。只有标量或普通 struct／tuple 的实际存储完整、无引用且无 padding，才计入覆盖范围；局部重赋值更新别名。调用、poll、条件分支、读取、取址、外传与未知操作结束分析，循环回边不继续遍历。使用现有完整值布局，取址局部集合在实际需要时按函数建立一次。

只取被完全覆盖的连续尾部，缩短原来的一次 memset；至少保留 16 B 对象头。引用槽、padding、enum／MaybeUninit 存储及未证明字节仍清零，原构造写入、对象起点发布、分配计数和 release-ready 顺序保持。被省去零写入的字节在下一次可观察操作前完成初始化，合作式 STW 与精确根规则不变。数组、动态／未知布局、带 release hook 的慢分配和 debug 沿原完整清零路径。跨 Cone 正文可用时沿相同规则处理，未展开调用结束分析；不扩充产物格式。

对象体积、接口表、GC roots、runtime ABI **16** 与 metadata ABI **9** 保持。优化只减少生成的零写入，不延迟登记，不复制构造正文，也不增加 runtime 判断。

## 定向验证

- 两机 fmt／workspace Clippy 通过；最终各 11 项分配 codegen 测试通过，覆盖跨块与局部快照、重赋值、读取／调用／取址／条件边界、引用槽、struct／tuple padding，以及 64／72／128 B 的目标策略。
- 三目标各运行 allocation-accounting、runtime-allocation、maybe-uninit-gc，共 6 个 profile 变体、24 次外部进程调用。debug／release、正常／移动／minor stress 均通过。新增构造中 GC、异常中断、泛型标量／引用／聚合字段和 padding 组合；保留既有装箱、128 B 边界及 catch 后继续分配覆盖。
- 收窄 x86 范围后，仅补每个 Linux 目标的 accounting 两变体、8 次进程调用，并测量最终产物。ARM64 最终程序、根 `.slib`、core 与已测候选逐字节相同，复用运行验证；未运行全量验收。
- 三目标最终 MIR／LIR 与基线逐字节相同，10 种负载的 16 项 GC 指标一致。每侧另核对 8 个模式、8 组零／短输入的数学结果。ARM64 的 24／48／128 B 函数分别减少 1／4／9 条机器指令；x86 的 24／48 B 分别减少 3 条。x86 128 B 函数经重定位归一化后与基线指令相同。

## 运行结果

使用[短命分配基准](../../tests/benchmarks/allocation/nursery/README.md)，双方配套工具与 core、相同 runtime，release 基础 CPU、一个 GC worker。一对预热后七对 AB／BA，GC 诊断另跑。ARM64 为 M3 Ultra／LLVM 22.1.8，GNU／musl 为 nuc12 i7-12700H／LLVM 22.1.2、CPU 4。下表为包含初始化、登记、统计和收集的阶段中位数，百分比表示耗时变化。

| 负载与次数 | ARM64 Darwin，ms | GNU，ms | musl，ms |
| --- | ---: | ---: | ---: |
| 24 B，2000 万 | 52.684→50.870（−3.44%） | 70.091→67.596（−3.56%） | 70.793→68.394（−3.39%） |
| 48 B，2000 万 | 70.973→58.528（−17.53%） | 94.410→89.008（−5.72%） | 95.648→90.969（−4.89%） |
| 128 B，1000 万 | 61.604→45.374（−26.35%） | 94.377→95.543（+1.24%，保留原清零） | 97.442→97.342（−0.10%，保留原清零） |
| 16 B 空对象，2000 万 | 46.672→47.056（+0.82%） | 61.684→61.641（−0.07%） | 62.092→62.082（−0.02%） |
| 536 B 数组含初始化，100 万 | 99.368→99.365（约不变） | 58.990→59.114（+0.21%） | 68.507→68.524（+0.02%） |
| 136 B，1000 万 | 85.714→85.018（−0.81%） | 126.742→126.563（−0.14%） | 166.437→166.580（+0.09%） |
| release hook 旧代对象，100 万 | 30.301→31.530（+4.06%） | 44.443→44.439（−0.01%） | 52.257→52.276（+0.04%） |
| 无分配整数对照，2000 万 | 6.290→6.204（−1.37%） | 2.641→2.638（−0.12%） | 2.598→2.597（−0.06%） |

24／48 B 的整进程墙钟分别降低 ARM64 2.54%／13.88%、GNU 3.30%／5.38%、musl 2.75%／4.27%；ARM64 128 B 降低 21.25%。单次／零次分配的阶段仅约 0.001～0.002 ms，启动占主导，整进程变化分别为 ARM64 +0.60%／+1.06%、GNU −0.51%／−1.11%、musl +0.04%／−0.08%，不作为单次分配收益。运行 RSS 中位数变化为 ARM64 −48～+48 KiB、GNU 0～+12 KiB、musl 0。

ARM64 hook 对照另做九对复测，31.138→31.992 ms（+2.74%），整进程 +1.26%。该函数经重定位归一化后指令一致、位置改变；保留这笔已观察成本，代码布局继续独立测量。

最初 x86 128 B 试验减少 7 条指令，同时出现新的累加器栈存储。GNU 首轮 −0.56%；musl 首轮 +1.59%，独立九对复测 −9.24%，两轮绝对耗时区间也不同。该范围未形成稳定结论，最终 x86 只采纳不超过 64 B 的区域，没有为未采纳试验增加公开选项。
