# 动态接口目录查询的测量与取舍

本轮保留新的测量负载和边界测试，**未采纳接口目录循环展开**。当前动态查询继续逐项比较 TD 指针；已有父表直接投影、接口检查与取表合并保持。没有新增优化开关、目录布局或 ABI。

## 实际目录与查询路径

对现有分配基准及其 core 依赖的可执行文件检查了 1,612 个 TypeDescriptor：1,487 个目录为空；125 个非空目录中，59 个只有一项，5 个两项，13 个三项，24 个四项，其余为 5、6、7、12、15 项。数值装箱类型达到 12／15 项，String 为 7 项，所见 ArrayList 实例为 6 项。静态数量包含抽象类型等描述符，不表示运行时访问频度。

目录按 persistent exact interface identity 排序。该顺序与 runtime type ID 的数值顺序不同；已知具体类型的静态目录索引和跨 Cone dispatch 记录使用同一序列。因此只替换 runtime 循环为二分查找不成立。父表的完整内嵌布局、目录顺序及真实调用 ABI 是不同的合同。

扩展[接口基准](../../tests/benchmarks/interfaces/README.md)的模式 9～17，覆盖装箱 Int 的早／中／末段接口、泛型未命中、空／单项目录、ArrayList 的 Collection 视图、纯 Boolean 检查以及成功／失败混合。保留原有静态类型、已有视图、一次转换、每轮转换和父接口投影对照。对象在计时前构造，各模式使用同样输入比较。

机器码确认 main 仍调用 provider 的查询内核，numericHash 的三个来源分别保留调用；没有通过调用方内联丢失未知实际类型。provider 中实际视图消费者调用 `itable_find`，纯 Boolean 模式调用 `is_instance`；已有父表投影保持零目录查询。

## 本机试验

基线为 `0aedbaa92`，M3 Ultra／Darwin，双方使用同一 release 编译器和源码。每个长模式 2,000 万次，一对预热后交错测量七对；普通计时与 GC 诊断分开。另核对零次和单次输入。下表为阶段墙钟中位数变化，负值表示加快；每行与该轮交错运行的基线比较。

| 扫描写法 | Int Add，中段 | Int Mul，末段 | 泛型未命中 | 主要回退 |
| --- | ---: | ---: | ---: | --- |
| 四项一组，余项逐项扫描 | −12.16% | −18.57% | −25.36% | 空目录 +19.58%，单项目录未命中 +21.18% |
| 增加空／单项目录直接结果 | −12.15% | −16.57% | −22.65% | 每轮单项转换 +6.73%，Collection 查询 +9.57% |
| 先检查首项，再分组扫描 | −15.92% | −19.79% | −26.69% | Child smartcast +13.93%，单项未命中 +20.76% |
| 每项检查剩余长度的四项展开 | −16.67% | −15.68% | −14.85% | Child smartcast +11.37%，单项未命中 +22.40% |

单项目录未命中的绝对回退约为每次 0.21～0.23 ns；空目录首轮约为每次 0.24 ns。成功／失败混合模式改善约 1.65%～7.80%，但各写法都存在其他重要负载的回退。没有据某一组中后段结果选择默认策略。

四种候选的机器码增加 284～440 B，EH 信息增加 16 B，完整程序增加 48 B；provider／consumer 的 MIR、LIR、两份 `.slib` 和全部 16 项分配／GC 计数保持。92 个普通 runtime 目标文件中只有 `rt.c` 对应的一个变化；最终链接位置随目标文件内容变化，表中保留实际布局下的全部结果。Linux 编译预检查发现 GCC 会将较大的 helper 保留为独立调用，普通 `inline` 标记可消除这一层调用；这不能代替 Linux 的运行收益测量。

短目录代价与中后段收益尚未形成合适的默认取舍，本轮恢复原扫描。没有将实验实现发布为默认能力或为其增加 runtime 构建选项。循环中的查询提升、运行时缓存或其他目录布局仍须独立证明其实际适用范围和收益；本轮没有实现这些方案。

## 最终保留与验证

- runtime／实现规范明确现有目录顺序、TD 指针身份、完整 exact 泛型、空目录及读取边界；不改变语言行为、对象、接口值、roots 或 ABI。
- 既有 C 查询专测改用 O2，新增 0～17 项目录的逐位置查询、目录外目标和 null slots 组合。两机各一项定向测试及 workspace Clippy 通过。
- 三目标各验证 9 种新增负载的 0、1、2、3、4,097 次输入，按数值运算和 Hash 算法检查校验和。使用真实跨 Cone CLI 构建与配套预编译库；没有全量验收。
- 本机试验阶段另通过接口视图与跨产物的 4 个正式变体、10 次进程调用。回滚后，普通／stress runtime 各 92 个目标文件、生成程序和两份 `.slib` 与基线逐字节一致，查询实验没有留在开发 sysroot 中。

本机准备脚本的一次调用进入了未受影响的系统库构建，发现后结束该任务，随后直接使用已有 runtime 构建入口完成试验与恢复。Linux 只验证保留的测量载体及 O2 边界覆盖。原始数据、试验源码、机器码和日志仅留在两机忽略的 `tmp/program-performance/interface-directory`，不提交。
