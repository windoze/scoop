# 叶函数调用成本评估

本批结论为**暂不采纳**：有界分支叶函数省入口 poll、统一函数对齐及无 safepoint 叶函数省帧均未进入默认配置，也未增加公开开关。主线保留原有 poll 资格和 frame-pointer 策略。省帧实现及定向回归保存在本地分支 `codex/leaf-frame-experiment-20261026`（`1834e8386`），未推送。

## 基线与测量范围

普通应用以 `de03af3d3` 为基线，固定源码、接口布局、预编译系统库及 runtime，仅更换编译器。Darwin 使用 M3 Ultra／LLVM 22.1.8；GNU、musl 使用 NUC12 i7-12700H／LLVM 22.1.2，计时固定 P-core CPU 4。性能使用正常 release，GC 诊断另行运行。

常规对照为一次预热、五对 AB／BA。复用现有跨 Cone 成员基准，动态接口调用和已内联的标量对照各执行两亿次，保留内核及进程时间；先核对六种模式在 0、1、2、3、4097 次时的结果。主线恢复后没有把候选程序的时间差计为已交付收益。

对此前整字存储的 musl 回退另取硬件计数：旧 byte→word 对照的 dispatch／List<Long> 动态指令数分别保持约 75.81／103.42 亿，cycles 中位数增加约 6.4%／11.2%；frontend-bound 从 45.10%→48.63%、23.14%→29.80%，分支失误没有相应增长。不能将这部分回退归于新增指令或主要 off-CPU 等待；具体布局原因仍未完全定位。

## 有界分支叶函数与对齐

候选扩展原有直线叶函数分析，允许无环条件分支、共享合流和多个正常返回，全部可达块仍合计不超过 64 条操作，每次值复制不超过 64 B。任一路径出现调用、分配、异常、循环或 native／全局存储访问均保留入口 poll；gateway 规则不变。

它消除了常量除法展开后残留菱形 CFG 对免 poll 资格的阻碍。dispatch 中对应 callee 的 ARM64 静态指令从 17→8，text 少 36 B、stackmap 少 128 B，循环正文不变。但进程耗时在 ARM64／GNU／musl 分别变化 **+13.96%／+20.26%／−23.35%**。NUC 上动态指令减少约三亿、分支减少约五千万，失误次数基本相同，仍不能以指令减少代替收益验证。

统一 32 B 函数对齐没有修复 ARM64 回退，且削弱了 musl 的收益。这两个候选均撤回，没有按函数名称或特定基准保留例外。

## 独立省帧候选

此候选保留原有直线免 poll 资格，只消费已有 callable 与 site manifest：没有任何已规划 safepoint 的实际定义可使用 LLVM `frame-pointer=non-leaf`。含 site 的函数始终保留帧指针，零 root 的 site 也不例外；实际机器调用、动态栈等需求仍由 LLVM 保留帧。没有把 NoGc 标志等同于无 site，也没有改变 ABI、接口表示、根恢复或 caller 的 Managed effect。

ARM64 成员基准的真实动态调用仍存在：caller 保持 41 条指令及间接调用，callee 从 7→4 条指令。两亿次动态调用的内核中位数从 **261.586→213.861 ms，降低 18.24%**；标量对照降低 0.55%。GNU／musl 的同一动态内核却分别增加 **3.69%／2.77%**，标量对照变化 −0.22%／+0.33%。

ARM64 普通程序的完整进程中位数如下，正数表示变慢：

| 程序 | 基线 → 候选 | 耗时变化 |
| --- | ---: | ---: |
| dispatch | 442.629 → 449.731 ms | +1.60% |
| lambdas | 158.285 → 156.644 ms | −1.04% |
| List<Long> 迭代 | 402.378 → 396.093 ms | −1.56% |
| 接口数组复制／父投影 | 125.832 → 134.776 ms | +7.11% |
| class 引用跨调用 | 59.172 → 59.270 ms | +0.17% |

只对接口数组的明显回退复测原二进制，一次预热、九对 AB／BA 得到 **125.838→135.247 ms，增加 7.48%**；CPU 时间同样增加。其 copies 正文均为 305 条指令，入口前移 48 B；不能仅凭地址变化就宣布已证明具体的微架构原因。分配均为 1,051,744 B、minor 均为一次、root slots 均为 72，布局和父投影路径保持。

GNU／musl 四种普通程序的候选变化分别为 −3.23%～+1.46%、−4.53%～+0.61%。一度尝试仅保留 ARM64 选择：GNU／musl 的五个程序及成员 provider、consumer、可执行文件均恢复为基线相同字节；ARM64 仍与上述省帧候选逐字节一致。接口数组复测后撤回该选择，没有将微内核收益扩展为综合性能结论。

## 正确性与成本

两机先格式化及 release Clippy，再完成有界叶函数的 42 项 LIR 定向测试、省帧的 57 项 statepoint 测试；收窄目标选择后只重跑相关两项机器码回归。覆盖三目标 debug／release、真实 NoGC helper 调用、零 root 的 Managed site。三目标的定向 GC fixture 均通过两种构建、12 次进程调用，验证普通／moving／minor 收集、接口及 niche 返回值和 native 线程组合。未执行全量 fixture。

ARM64 五个普通程序的 text 少 12～48 B，完整文件大小保持，stackmap 大小及分配／GC 计数保持；跨 Cone 成员 provider 少 74 B，consumer 和可执行文件大小保持。现有四个系统库和 runtime 原样复用，没有新增对象、roots 或测量代码。

使用两种代表程序进行冷应用构建，复用 sysroot、包含链接，一次预热、三对交错。ARM64 dispatch／lambdas 的墙钟变化 +0.51%／−0.28%，CPU −0.39%／−0.46%，峰值 RSS +0.17%／−0.31%。收窄选择后的 Linux 产物保持相同字节，构建墙钟差异 −0.55%～+1.84%；不将这些小幅差异解释为编译加速。决定不采纳的依据是运行收益不稳定，并非空间或编译成本。

原始日志、汇编、逐次 JSON 和复测在两机仓库外的 `scoop-performance-results/2026-10-26/hot-call-loops/`；工作目录及编译器快照在忽略的 `tmp/program-performance/hot-call-loops/`。后续继续处理实际 List 调用链及代码布局，既有已采纳优化保持。
