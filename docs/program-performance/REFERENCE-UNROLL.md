# 有界引用读取的部分展开

以 `8ea6f197f` 为基线，依据[函数级采样](CPU-PROFILING.md)中 `sumNodes` 的连续引用／字段读取热点，采用四倍部分展开。三个现有目标均为 release 默认能力，没有新增公开开关或等级。

本文保留首版单块范围与测量结果；后续已扩展至小型条件读取区域，当前范围和新增分布测量见[条件引用读取展开](CONDITIONAL-REFERENCE-UNROLL.md)。

## 设计与范围

先修订实现规范 2.19。复用已有常数有界区域，只选择单块、4～64 次且可被四整除的小型只读内层；正文最多 24 条非 phi／分支指令，包含实际 AS1 引用读取。允许普通引用／标量加载、AS1 地址计算及标量运算；新读取的引用和派生地址只在内层使用，稳定根槽复用原分析。含写入、调用、原子／volatile、提前退出、分支或引用递推的内层不取得展开资格。

- 保留原 64 次分块、外层 poll、根恢复和短尾；不提升普通根加载，不增加引用 SIMD 或放宽浮点计算顺序。
- 先分离可能共用的内外层回边，再添加 LLVM 的固定展开次数；关闭自动完整／部分展开、peeling 和运行期余数生成。未选循环继续沿用原策略。
- 与卡标记合并共享现有边拆分工具。前序变换更新区域的实际出口；冗余元素写入已经消除、但卡标记仍须保留时，后续读取展开仍在正确的标记／poll 之前结束。
- MIR／LIR、对象与接口布局、GC 和 `.slib` ABI 均不变，继续复用既有父接口静态投影。

## 定向验证

两机格式化、workspace Clippy 和 18 项有界循环后端测试通过。新增覆盖 4／8／64 次、常数外层、严格浮点归约、引用不逸出内层，以及写入、调用、atomic／volatile、提前退出、不合格次数等拒绝路径。三个目标均通过 LLVM safepoint verifier、精确根与真实对象／stackmap 发射。

[引用数组优化合同](../../tests/fixtures/compiler-correctness/optimization/lowering/reference-arrays/fixture.toml)及[引用数组根与屏障](../../tests/fixtures/gc-correctness/poll/reference-arrays/fixture.toml)在每个目标通过两组 fixture、三个变体、13 次进程调用，覆盖 debug／release、短尾、边界、接口／装箱／wrapper 与并发 moving／minor。没有全量验收或重建未变化的系统库。

回归先后捕获并修正了展开提示被复制到外层、卡标记合并后仍使用旧出口的问题。最终两机 18 项后端测试通过；三个目标的最终基准 `.slib` 与已测候选逐字节相同，复用对应运行／GC 数据，编译成本以最终工具重新测量。

16 种模式输出一致；完整 LIR、235 条 TD／接口表／布局定义及原 poll／live 集合保持。22 种负载的 15 项分配、GC、脏卡和扫描计数均相同。真实 `sumNodes` 内层从 ARM64 每元素 6 条指令变为每四元素 14 条，x86 从每元素 5 条变为每四元素 11 条；原短尾保持。其余已检查内核的指令数量没有变化。

## 收益与成本

使用相同[引用数组基准](../../tests/benchmarks/arrays/references)、预编译 core／runtime 和输入。机器为 M3 Ultra／LLVM 22.1.8、nuc12 i7-12700H／LLVM 22.1.2，Linux 固定 CPU 4。普通 128 轮、短路径 10 万轮先做一对预热及七对 AB／BA，并单独收集 GC 数据。

为减少短阶段波动，另在 ignored 临时源码中仅将长路径轮数改为 4096；65,536 个元素，两对预热、11 对 AB／BA。以下为该较长阶段的墙钟中位数变化，负数表示降低；对照项没有取得新的展开资格。

| 操作 | Darwin ARM64 | Linux GNU | Linux musl |
| --- | ---: | ---: | ---: |
| Node 字段求和 | −13.46% | −3.63% | −3.59% |
| 末项身份搜索对照 | −0.48% | −0.82% | −0.59% |
| 可空 Node 求和对照 | −0.21% | −0.03% | −1.17% |
| Long 数组求和对照 | +0.57% | −0.33% | −0.02% |

求和的配对变化中位数分别为 −13.49%、−3.29%、−3.41%。本机两倍展开为 −8.86%，因此选择四倍。128 轮初测中 Darwin 搜索对照一度为 +31.22%，其热循环指令与地址均未改变，上述较长阶段没有复现；不把未变内核的偶然涨跌归为本项收益。短路径保持原实现。这些是所选内核的描述统计，尚未据此完成通用应用或跨语言性能比较。

| 成本 | Darwin ARM64 | Linux GNU | Linux musl |
| --- | ---: | ---: | ---: |
| 应用 text 增量 | +40 B（约 0.005%） | 0 B | 0 B |
| 应用 `.slib` 增量 | +32 B | +32 B | +32 B |
| 最终程序文件增量 | 0 B | 0 B | 0 B |

编译成本交错执行六轮双方独立应用编译，首轮预热不计，取其余五轮中位数。有限代码增长与三目标一致的读取收益支持当前 release 默认策略；更大倍数、条件／写入循环展开继续另行测量。原始记录保存在 `tmp/program-performance/reference-unroll`，不提交实验工具或逐次日志。
