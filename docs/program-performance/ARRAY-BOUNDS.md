# 普通数组遍历的边界检查与分块

## 已确认的瓶颈

以 `c4390283f` 为基线，真实 Array／MutableArray 的 get／set 已展开为 MIR 数组操作，但每次访问仍有负索引、长度比较和异常分支。`while (i < values.size)` 的长度 getter 形成直线 header 链，缓存的 `val count = values.size` 则形成循环前的赋值；这些常见上界也未进入现有分块识别。

本项推进调研 §6.1 的普通读取、原地变换和数组间复制，复用已交付的 64 次分块及受限 LLVM 内层优化，不提高内联阈值或开启一般 Managed 循环变换。

## 设计

从实际归纳变量和 typed 数组引用建立必要范围事实，按语句次序传播局部快照。稳定参数、进入循环前已经保存的上界，以及同一稳定数组的长度均可参与证明；取址、重赋、未知来源和未能解释的条件保留原路径。复用现有支配关系分析，允许定义支配 header 且不位于该循环正文区域的单次定义；这覆盖被内联到外层遍历中的访问，而非只看紧邻 header 的前驱。仍要求非负起点、严格小于上界和唯一加一更新。

同一数组长度作为上界时，负索引与上界失败分支不可达，可在原循环中直接去除并复用完整块／尾部的现有分块。不同数组或显式 count 需要额外关系时，在原 poll 和进入正文的条件之后检查 `count <= array.size`；仅为至少 64 次的完整块建立无检查内层，其余进入原有标量路径。条件失败不抛错，越界前已写入的元素和 RHS 副作用保持。

只复制已证明执行的直线路径，不复制异常构造和 GC site；数组对象继续使用普通 roots，派生地址不跨外层 poll。LLVM 依据实际别名关系决定是否向量化，数组相同或重叠不被假定为不相交。

## 定向验证

Rust 格式化、workspace Clippy 与固定版本 Ruff 通过；5 项既有 MIR 分块测试通过，包含临时值重赋快照与归纳变量唯一加一的回归。没有修改 codegen／runtime，也没有重复上一项的完整代码生成验证。

Darwin ARM64、Linux GNU／musl 各通过两组正式 CLI 专测，每目标共 3 个 variant、12 次进程调用；没有运行完整验收：

- [检查消除与原回退](../../tests/fixtures/compiler-correctness/optimization/lowering/array-bounds/fixture.toml)：debug／release 的实际 MIR 与运行结果，包含直接／缓存长度、显式 count、不同数组／同数组复制、内联到外层循环的求和，以及 0、1、63、64、65、127、128、129、1025 个元素。验证 Int 回绕、负／零 count、源或目标过短、异常前已写前缀与 RHS 副作用；数组重赋、步长 2 和负起点保留原路径。
- [数组根与并发 GC](../../tests/fixtures/gc-correctness/poll/array-bounds/fixture.toml)：两个 callback mutator 各对 64 对 2049 元素数组执行变换、复制与逐项校验，同时请求收集；moving／minor 均通过。MIR 确认实际受测的 transform／copy 已生成完整块，沿用 100 µs NativeSafe 收集请求间隔。

第一次性能检查发现，原识别只接受紧邻 header 的稳定赋值，导致实际内联后的复制未命中。复用已有支配分析后修正，增加嵌套求和回归并重新完成受影响的验证和测量。综合调用者中的另一处 getter 仍未展开，早期把它也算作应当分块的测量断言因而失败；确认真实保留原因后，将未命中对照和独立求和路径分别记录。早期失败批次不记作最终通过。

## 生成代码与运行测量

以 `c4390283f` 为基线，双方均使用普通 release、同一预编译 sysroot 和生产 runtime。Darwin 为 M3 Ultra／LLVM 22.1.8，GNU／musl 为 nuc12 的 i7-12700H／LLVM 22.1.2；采用基础目标，不使用 `-march=native`。固定一个 GC worker，GC 统计另跑，不混入计时。

[数组遍历基准](../../tests/benchmarks/arrays/counted.scoop)复用现有 [phase companion](../../tests/benchmarks/interfaces/phases.c) 和 [A/B 测量入口](../../tests/benchmarks/compare.py)。`SCOOP_BENCH_KIND=0/1/2/3/4/5` 分别选择综合求和、原地变换、不同数组复制、同数组复制、NoGc 对照、独立求和；`SCOOP_BENCH_COUNT` 选择元素数。大数组为 65536 个元素、128 次遍历，短数组为 1 个元素、100000 次遍历；分配／初始化位于 phase 外，最终结果在 phase 后输出。每模式一对预热、七对交替 AB／BA 样本，双方输出一致。以下为同机独立样本中位数，不是跨语言排名或显著性判断。

| 目标 | 独立 Long 求和 ms | Int 原地变换 ms | 不同数组复制 ms | 同数组复制 ms |
| --- | --- | --- | --- | --- |
| Darwin ARM64 | 7.771 → 2.605（−66.48%） | 9.808 → 0.702（−92.84%） | 10.620 → 2.273（−78.60%） | 7.514 → 2.524（−66.41%） |
| Linux GNU | 4.813 → 2.719（−43.51%） | 5.473 → 1.052（−80.77%） | 6.127 → 2.869（−53.17%） | 4.785 → 1.080（−77.44%） |
| Linux musl | 4.822 → 3.015（−37.48%） | 4.800 → 1.012（−78.92%） | 6.122 → 3.284（−46.36%） | 4.784 → 1.088（−77.26%） |

对应四种模式的整进程耗时分别降低 Darwin 18.48%／30.08%／26.85%／17.50%，GNU 11.17%／28.48%／17.85%／21.01%，musl 2.49%／9.37%／9.93%／12.42%。进程计时包含启动、初始化与退出，不能代替内核时间。

生成代码核对覆盖真实执行的调用者：`exercise` 的完整块由 3 个初始化块增至 5 个，增加两种内联复制；不同数组有 2 个长度 guard，同数组只有 1 个。`reduction` 的完整块从 1 个初始化块增至 2 个，新增求和。二者 LIR poll 位置分别保持 8／4 个，完整块中没有逐元素 bounds check、调用或新增 poll。独立 sum／transform 中不可达异常分配消失；copy 的原 checked fallback 与两个 throw 继续保留。

实际原地变换生成 ARM64 NEON 的 `mla.4s` 和 x86-64 的 `paddd`／向量 load-store；独立求和及基准中内联的不同数组复制仍是标量内层，收益也来自检查与动态 poll 次数减少，不能全部归因于 SIMD。独立 copy 在 x86-64 另有 LLVM 生成的向量路径，实际调用者的结果单独核对，没有用未执行的独立函数替代证据。

综合求和仍保留 `Array<Long>.get` 调用。已有优化报告明确记录其增长成本 35 超过 caller 剩余额度 24；本项没有调整阈值。该模式内核变化 Darwin −0.13%、GNU −0.11%、musl −0.27%，基本不变，不能把独立求和收益套用到它。NoGc 对照归一化地址后的指令序列完全相同，内核变化 −0.02%／−0.52%／−0.12%，保留为测量波动。

| Darwin ARM64 | −0.36% | +1.89% | +4.18% | +0.72% |

动态短循环仍付出完整块选择与布局成本；guarded 路径不足 64 次时继续执行原 checked 正文。最大绝对回退为 GNU 同数组复制 0.173336 → 0.245015 ms，即约 0.72 ns／次遍历，该模式整进程 +14.35%；没有隐去这一回退。综合求和短循环变化 −0.75%／+6.00%／+6.19%，也保留在原始记录中。

| --- | --- | --- | --- |
| Darwin ARM64 | 707802 → 705580 | 1018704 → 1018952（+248） | 18022648 → 18021224（−1424） |

代码复制增加少量 text，去除不可达错误路径使根 `.slib` 和完整文件变小。每目标的 64 条 TD／接口表／布局记录逐字一致，所有 ABI 保持。11 种负载的分配、nursery 分配、minor／full 次数、晋升、复制和 root slots 统计相同；普通计时运行没有发生 GC，移动正确性由上述专测验证。

只编译根 Cone、消费已预编译依赖，关闭观察输出，使用一对预热和五对正式 AB／BA 样本。编译墙钟中位数 Darwin 1.0222 → 1.0315 s（+0.91%），GNU 1.4963 → 1.5802 s（+5.61%），musl 1.5040 → 1.5134 s（+0.62%）；CPU 时间变化 +0.76%／+5.80%／+1.12%，峰值 RSS 变化 −0.84%／+0.08%／+0.11%。这些是本基准的编译成本，不代表整个标准库。

此有限范围沿用 release 默认能力：长数组收益在三目标成立，静态体积与内存成本小，动态短路径保留原语义；短循环和编译回退继续作为后续优化依据。本项不引入开关、持久 IR 字段或第二套循环框架。尚未展开的 getter、浮点、引用／聚合元素、非单位步长、复杂条件和含调用／EH 的循环仍需分别处理；内联净成本、短循环选择及内层基址加载仍有继续改进的空间。

原始日志、JSON、IR、反汇编及早期失败记录保留在两机忽略的 `tmp/program-performance/array-bounds`；文档只保存结论和限制。
