# 普通内联增长额度

当前的收益、热度、累计增长和正文尺寸选择由[调用点内联评分](CALL-SITE-INLINING.md)接续；下面保留本项交付时的设计与测量。

相对 `3763249c1`，普通 MIR 内联的初始 caller 增长额度从 `min(size / 2 + 96, 384)` 调整为 `min(size / 2 + 128, 384)`。统一适用于本地函数、具体化泛型及跨 Cone 普通正文；release 默认启用，没有按库、类型或函数名称特殊处理。执行成本阈值、384 的总上限、六层展开、稳定模板、三轮优化及跨轮累计扣减保持；同步 suspend 内联仍使用原初始常数 96。语言、对象／GC、`.slib` 与调用 ABI 不变。

## 选择与边界

真实 ArrayList 遍历的第三轮中，`get` 的执行成本为 19、增长为 13。原 caller 只剩 3 单位，因增长保留调用；调整后该点剩 35，执行上限为 36，可以正常入选。`ArrayList.get` 调用在 MIR 和三个目标的实际机器码中均由一次变为零。索引检查及 `MutableArray.get` helper 仍受同一成本限制保留调用，不宣称整条访问路径已经没有调用或检查。

先前考虑的跨轮按实际保留大小回收额度没有在此负载解开限制：展开后的中间值仍被现有大小模型计入。该试验未采纳，补丁与产物只留在忽略的临时目录；本项选择较小的统一参数调整，不增加另一套成本模型、增长返还或可插拔策略。

## 定向验证

- 两机格式化／workspace Clippy 通过；66 项 MIR 优化测试通过，包含递归、六层展开、跨轮增长、冷分支、参数快照、异常、局部分配和 roots。冷分支用例扩大到新的额度之外，并明确断言因增长拒绝，而非仅断言调用尚在。
- 三目标通过 `inlining-growth`、`inlining-semantics`、`inlining-release`、`local-class-scalar-roots`，共 21 个 variant、54 个进程。增长专测加入真实 ArrayList 遍历、MIR／决策检查与独立预期输出；引用字段组合覆盖 moving／minor GC。
- 本机另运行 5 项相关优化快照专测，共 10 个 variant、28 个进程。逐项审阅 `inlining-decisions` 与 `devirtualization-locals` 中新增展开、常量传播和相应块重编号；其余 3 项与 debug 期望均未变化。没有运行全量验收。
- [现有 class／集合基准](../../tests/benchmarks/allocation/README.md)保留 Point、Cursor 与标量对照。三目标两版各验证 4 模式、4 种迭代次数，共 96 个独立参考输出。12 组独立 GC 诊断的 16 项计数均一致；Point／Cursor／标量分配 112 B，ArrayList 分配 296 B。

## 性能与成本

M3 Ultra／LLVM 22.1.8，Linux 为 `nuc12` i7-12700H／LLVM 22.1.2、绑定 CPU 4；使用同一组预编译 core／std／runtime，仅应用编译器版本不同。每项一组预热、7 组 AB／BA。Point／标量为 200 万次，Cursor／ArrayList 为 50 万轮，每轮消费 16 个值；表内为不含启动与编译的内核墙钟中位数，单位 ms。
