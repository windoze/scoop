# 循环中稳定来源的接口查询复用

状态：实现与三目标定向验证完成，release 默认启用，无新增公开开关。以 `db3def6c8` 为基线，接续[检查与取表合并](INTERFACE-CHECKS.md)，使用[动态接口目录负载](INTERFACE-DIRECTORY.md)评估。

## 选择与边界

在循环中反复检查同一个对象的同一个 exact interface 时，第一次实际检查执行 `itable_find`，此后复用静态 entry，包括 null 未命中。每个组合只保存 metadata entry 和已初始化 Boolean，不保存对象副本；空接口的非 null entry／null slots 与未命中分别处理。检查及成功视图共用同一 entry，每次视图仍从当前 managed 引用取得 object，移动 GC 后保持有效。

来源必须是未取地址、未写入的参数，或只有一次写入且该写入不在任何正常／异常 CFG 环中的非空引用局部值。只有至少一个同源同接口检查可能重复执行时才创建状态。函数入口只初始化状态；首次查询留在原求值点，零次循环、未进入的条件和查询前的异常不提前查表。独立 prologue 避免 MIR entry 回边重新初始化缓存；实际 loop poll 责任保持。稳定参数可跨 catch 复用，异常回边上的重复初始化不能当作稳定来源。

适用的 `is`、`as`、`as?` 和纯 Boolean 检查使用同一路径。循环中重新创建／赋值或从字段／全局／指针逐次读取的来源继续原查询；同一 exact 泛型实例独立保存结果。普通单次检查不增加状态，debug 保持原 lowering。已有 Child → Parent 的完整父表投影和继承方法取槽仍为零目录查询；首次 Any 查询及没有可复用结果的动态关系仍扫描原目录。独立的、未被检查覆盖的 `itable_lookup` 路径不在本项范围内。

实现只增加函数内普通 LIR locals 与分支，在最终 GC roots 生成前完成；不改变对象体积、接口双字表示、父表布局、跨 Cone／`.slib` 格式、runtime ABI 16 或 runtime 查询实现。

## 正确性与生成代码

- 两机格式化、workspace Clippy 和 23 项接口 lowering 测试通过，包括单次局部定义、参数、重赋／取址排除、Boolean／空接口、独立 exact 接口、异常回边、入口回边与原父表投影。代表性调用的 managed locals 和 live roots 与旧路径相同。
- Darwin ARM64、Linux GNU／musl 各通过 `interface-view-reuse`、`interfaces-artifacts`、`conditional-interface-roots`，覆盖 debug／release、反向跨 Cone、独立链接、泛型、装箱、default／override、moving／minor GC。补充的循环 `as` 失败后 catch、`as?` 命中／缺失、零次循环在三目标两种 profile 通过。只运行这组定向验证。
- 新目录负载各以 0、1、2、3、4097 次核对数学结果；长计时 A/B 输出相同。GC 统计另测，20 种输入的 16 个分配／收集／扫描计数分别保持一致。
- LIR 与最终机器码确认：合格路径的查询受“尚未初始化”分支控制，成功与失败都在首次查询后记录；循环热路径不再逐次调用 find。Boolean 路径从逐次 `is_instance` 改为同一 entry 的存在性判断。循环内切换来源的 `mixedHash` 保留逐次查询；父表投影仍无 lookup。
- 两版 provider MIR 相同，consumer LIR／`.slib` 相同。通过最终符号地址核对 main 的真实调用，保留 provider 的未知实参边界，没有以调用方内联／静态类型折叠代替测量。

## 运行结果

复用接口基准，双方预先构建并消费同一预编译 sysroot。每个长模式 2,000 万轮，一对预热、七对 AB／BA；普通计时关闭 GC stress／统计，GC 另测。Darwin 为 M3 Ultra／LLVM 22.1.8，Linux 为 i7-12700H／LLVM 22.1.2，固定逻辑 CPU 4。下表为内核墙钟中位数的变化，负数表示更快，不表示一般应用或跨语言综合性能。

ARM64 短目录 `as` 从 89.408 ms 增至 93.278 ms，摊到每轮约增加 0.19 ns；确实消除了重复 find，但增加状态分支与寄存器保存，栈帧从 144 B 增至 160 B。smartChild 基本持平，不能承诺所有短目录方法调用变快。零／一次调用的整个测量区间约 1～5 µs，精度不足以从百分比判断单次初始化的纳秒成本；两者的查询次数及结果已独立验证。

静态投影对照也保留实际测量：GNU 的 secondary／diamond 分别 −16.13%／−10.54%，musl 则 +17.92%／+12.85%。这些函数的 LIR 完全相同，x86 均为 89 条指令，除符号重定位外指令与操作数相同，入口／调用位置改变；不能把这组变化归功于或全部归咎于查询复用，具体微架构原因未作硬件计数器归因。其余静态／单次转换对照变化在 −1.08%～+1.64% 内。原始数据完整保留，不据单个负载调整函数布局。
