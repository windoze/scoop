# 严格浮点数组循环

## 依据与实现边界

基线 `78e0fc7a0` 中，整数／Boolean 数组已经可以消除适用的边界检查并形成 64 次无 safepoint 内层；MIR 与 LLVM 的选择仍排除 Float／Double，使相同结构的初始化、逐元素变换和有序求和保留逐轮 poll。

本项复用原有稳定长度、索引快照、动态 guard、尾块与 moving GC 证明，仅扩大能表示为标量的真实类型和操作。MIR 通过 intrinsic representation 识别 Float／Double，不按名字或任意 GC-free struct 推断。LLVM 仅允许整数／浮点标量 SSA 及普通 AS1 元素访存；调用、指针合流、volatile／atomic 与根槽写入仍排除。

不增加 fast-math，不允许乘加融合或重结合。每个元素保持原精度和舍入次数；求和继续保留源码的累加顺序，向量化交给 LLVM 的有序归约能力，未命中则保留标量。NaN、Infinity、负零、subnormal、零长度、尾块、别名和异常前缀均沿原语言合同。

LLVM 22.1 的启用向量化 hint 默认允许浮点重排，即使输入没有 fast-math 标记。首次 release 语义专测捕获了这个问题：顺序执行 `16777216f, 1f, -16777216f` 的累加被改成了分组累加；改动前的 release 编译器通过同一用例。现在统一设置 `hints-allow-reordering=false`，并用独立后端回归覆盖 Float／Double，保留实际逐元素 SIMD。本项未推送该不正确的中间产物。

## 定向验证

Rust 格式化、workspace Clippy、Ruff 0.16.10 通过。本机 5 项 MIR 计数循环回归与 5 项后端回归通过；Linux 使用本机 LLVM 再通过同组 5 项后端回归。后端用例覆盖三个 target 的实际向量访存、禁止重排、原子／volatile 等保留路径，以及 RS4GC 与机器 site／roots。

三个目标各通过两组正式 CLI 专测，每目标 3 个变体、12 次进程调用，没有运行全量验收：

- [严格浮点数组](../../tests/fixtures/compiler-correctness/optimization/lowering/float-arrays/fixture.toml)：debug／release 均检查 0、1、63、64、65、129、1025 个元素。覆盖初始化、乘加、除法、缩窄、同数组别名、顺序求和、NaN payload／signed zero 的复制、subnormal、除零、禁止融合和较短目标数组的异常前缀。MIR 精确检查实际内层及原 poll。
- [并发 GC](../../tests/fixtures/gc-correctness/poll/float-arrays/fixture.toml)：两个 callback mutator 各执行 64 轮 2050／2051 元素的初始化、变换、缩窄和求和，同时请求收集；moving／minor 均通过，保留 100 µs NativeSafe 请求间隔。与性能基准共用同一个 kernel 源文件，并检查真正命中的 MIR。

## 生成代码与运行结果

使用同一 [浮点数组 Cone](../../tests/benchmarks/arrays/floating/README.md)、既有 phase companion 和 A/B 工具，双方均为普通 release、相同预编译 core 与生产 runtime、一个 GC worker。Darwin 为 M3 Ultra／LLVM 22.1.8，GNU／musl 为 nuc12 i7-12700H／LLVM 22.1.2；使用基础目标，无本机 CPU 特化。

11 个独立数组 kernel 各新增一个完整块，入口和原 header 的两个 LIR poll 保持；真实调用者中的四个数组初始化内层也完成分块。逐元素乘加、除法已生成向量运算，乘与加分开；复制及精度转换沿 LLVM 的合法内层选择。实际顺序求和仍为标量累加，每 64 次回到原 poll，没有以重结合换取吞吐。检查的函数均未出现融合乘加。

每模式一对预热、五对交替 AB／BA，结果位型一致。大数组为 65536 个元素、128 轮；单元素为 100000 轮。访问内核的创建在 phase 外；初始化模式明确包含分配。以下为内核耗时中位数变化，不是显著性判断或跨语言排名：

| 内核 | Darwin ARM64 | Linux GNU | Linux musl |
| --- | --- | --- | --- |
| Float 乘加 | −93.53% | −88.04% | −88.57% |
| Double 乘加 | −89.69% | −75.26% | −75.71% |
| Float 顺序求和 | −28.21% | −20.04% | −21.80% |
| Double 顺序求和 | −28.85% | −27.70% | −27.97% |
| Float 复制 | −92.81% | −87.94% | −88.05% |
| Double → Float | −92.61% | −58.14% | −78.99% |
| Float 除法 | −93.63% | −78.62% | −78.69% |
| Double 除法 | −89.41% | −50.32% | −50.48% |
| Float 分配及初始化 | −68.92% | −35.62% | −31.72% |
| Double 分配及初始化 | −67.10% | −19.13% | −13.27% |

例如 Float 乘加分别从 12.378／7.272／7.031 ms 降至 0.801／0.870／0.804 ms；Float 顺序求和从 7.763／4.584／4.601 ms 降至 5.573／3.665／3.598 ms。十种大数组模式的整进程耗时均下降，但启动占比会改变降幅，不能以 phase 百分比代替整进程结果。

六种单元素内核的变化范围为 −16.25%～+24.87%。保留 musl Float 求和 0.171580 → 0.214250 ms 的回退，约增加 0.43 ns／遍历；GNU Double 求和内核增加 22.05%、整进程增加 24.54%。这些短任务同时受固定开销、布局与调度影响，未将全部差异归因于同一因素。NoGc 对照的 LIR 与各目标的 14 条机器指令数量保持，内核变化仅 +0.28%／+0.18%／+0.10%。

## 空间、编译成本与策略

| 目标 | 根 Cone `.slib` bytes | 程序 text bytes | 完整程序文件 bytes |
| --- | --- | --- | --- |
| Darwin ARM64 | 1149138 → 1180612（+31474） | 739368 → 742768（+3400） | 12708968 → 12730456（+21488） |
| Linux GNU | 1396660 → 1432956（+36296） | 872529 → 876369（+3840） | 12409168 → 12421560（+12392） |
| Linux musl | 1398132 → 1434846（+36714） | 942142 → 945982（+3840） | 12018208 → 12026504（+8296） |

完整程序增加 0.069%～0.169%，根 `.slib` 增加 2.60%～2.74%。这包含完整块／尾部、别名与长度选择以及相应静态记录；Darwin 的 stackmap section 由 512808 增至 513872 bytes，也计入成本。每目标 116 条 TD／接口表／布局记录保持，14 个受检函数的 LIR poll live 集合保持。17 种负载的分配、nursery 分配、minor／full、晋升、复制和 root slots 统计相同；大数组初始化实际发生 full GC，单元素初始化发生 minor GC。本项没有通过减少分配量或收集次数制造收益。

编译测量关闭观察输出，仅编译根 Cone、消费实际声明的预编译 core；一对预热、五对正式 AB／BA。墙钟中位数 Darwin 0.9612 → 0.9849 s（+2.46%），GNU 1.3196 → 1.3654 s（+3.47%），musl 1.3900 → 1.3724 s（−1.27%）；CPU 时间分别 +2.48%／+1.45%／+1.49%，峰值 RSS −0.13%／+0.85%／+0.88%。负墙钟差不外推为编译加速。

本项沿用 release 默认能力，所有 profile 保持同一语言、对象与公开 ABI。真实长内核在三目标均获益，编译与空间成本有限；短数组回退如实保留。未新增用户开关、优化等级、持久 IR 字段或 PGO。更广 CFG、引用／聚合元素、一般有序归约 SIMD 和短路径选择继续按证据推进。

原始源码实验、产物、日志、反汇编和逐次测量保留在两机忽略的 `tmp/program-performance/float-arrays`。收尾清理本机 72 份旧增量会话，释放约 860 MiB，保留各 crate 最新会话。
