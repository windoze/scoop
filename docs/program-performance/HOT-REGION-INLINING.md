# 自然循环的内联增长分配

接续[调用点内联评分](CALL-SITE-INLINING.md)。`b700b9822` 的 lambdas 在整个 caller 累计消耗 819／820 单位后，收益评分已通过的 `checkIndex` 和数组 `get` 仍被拒绝；部分每轮一次的 iterator 工厂与 `toArray` 也因此无法继续暴露每元素路径。单独减少建表展开只能节省 28 单位。848～985 为 MIR 成本单位，不是机器码字节数。

复用支配关系与自然循环分析，用最内层自然 header 区分区域；多个 latch 合并，循环外和不可归约区域共享普通记录。各区域基数仍为 `B=min(原 caller size/2+128,384)`，静态频次档位允许 `B／2B／4B`；整个 caller 的累计上限为 `8B`，最多 3072 单位。同步 suspend 的基础常数保持 96。一次普通展开同时扣除所在区域与 caller 的 `max(预计净增长,1)`，重新分析和化简不返还；新暴露循环可以使用自身额度，整个 caller 的上限始终生效。

收益评分、热度权重、稳定模板与六层深度沿用原模型。诊断补充循环 header、区域和 caller 剩余额度；调用目标、正文可用性与递归约束判断先于增长耗尽。此项作为 release 默认策略，不增加开关、试内联或另一套布局／ABI；debug 保留普通调用。`--emit optimizations` 仍只控制编译器报告，不生成程序诊断代码。

## 实际决策与正确性

lambdas 的 `main` 累计增长由 819 增至 1429，最终 MIR 成本由 848 增至 1309。三个 `Iterator<Long>.next` 接口调用全部消失，iterator 工厂、已展开读取路径的 `get`／`checkIndex` 也不再保留独立调用。后续既有去虚拟化、字段替换、复制清理及数组循环优化继续处理展开后的正文。没有按函数名称选择，原源码及接口布局保持。

仍保留 map 结束处的一次 `toArray`：外层区域只剩 1，预计需要 75；最后一次估价的收益为 176、惩罚为 255，因此还受当前规模惩罚限制。共享 `toArray` 内的接口读取及 `ArrayList.get → checkIndex` 保持。建表的 `ensureRoom`、初始构造、打印及异常后备也保留。map／filter 的独立数组快照与相应复制没有被此项消除；静态循环深度仍不能准确表示扩容等条件路径的实际频次。

两机均完成 74 项相关 MIR 优化回归及 4 项同步 suspend 回归；新增用例覆盖独立循环、新展开循环、整个 caller 上限和跨轮不返还，已有自然循环用例补充多个 latch／EH 的 header 断言。三目标各通过 growth、call-sites、members、semantics 四组，8 个 variants、26 个进程，覆盖跨 Cone／profile、实参和值快照、异常、集合流水线以及 moving／minor GC。增长 fixture 的流水线检查真实调用消失，并以 0／8 轮的独立结果验证执行。

Rust 格式化、相关 crate 的 release all-targets Clippy，以及固定版本 Ruff 通过。三目标 lambdas／dispatch 开启与关闭优化报告的机器产物逐字节相同。没有运行完整 fixture 或 workspace 验收。
