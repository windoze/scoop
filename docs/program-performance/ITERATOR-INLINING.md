# 局部对象字段替换指导内联

状态：已实现并完成定向验证。基线为 `b9bb63158`，普通编译器实现同 `12a121cf9`；本项是[类字段替换](CLASS-SCALARS.md)之后的增量。

ArrayList 遍历已将 iterator() 与构造器展开，next() 已去虚化。实测该调用的模板成本为 71，代入实参后的成本为 67，使用已完成 intrinsic 展开的正文重新估价仍为 67，故问题不是旧 intrinsic 包装。现有循环／receiver 阈值为 44，预计增长为 61，而 caller 只剩 27。

原来的估价没有计入内联会使局部 ListIterator 的分配、别名和字段间接访问同时消失。现在将这部分收益与展开成本一起计算，真实 ArrayList 反复遍历已命中；全局阈值和普通内联策略保持。

## 实现与边界

- 复用分配来源、支配和跨创建迭代的别名分析。只有 ordinary declared class、没有 release hook、所有引用使用均可替换且只剩当前一个 receiver 调用时，才考虑共同估价。首版排除 EH；后续[异常路径证明](EXCEPTION-SCALARS.md)允许满足同一分配消除证明的异常区域参与估价。分析只在普通选择失败且有 class 参数时按需建立，同一次选择复用结果。
- 检查实际要展开的正文：receiver 及纯别名只用于普通字段读写；定义不能混入外来引用。调用字段中的其他对象不等于传出 receiver；把 receiver 返回、捕获、传给未知调用、取地址或观察身份会阻止这项估价。
- 执行成本和增长复用原操作／值复制权重，以展开后的字段局部操作，加上 caller 同时发生的删除与替换之差计算。冷分支继续只折扣执行成本；struct／tuple／enum 和接口副本仍按完整值复制计价，实参与字段初始化的副作用保留。
- 每次选择仍至少扣减一单位 caller 增长额度，不返还过去的额度、不重置跨轮限制；递归与展开祖先规则保持。只有启用分配消除时才使用这一估价，最终改写由现有字段替换执行，发生在 LIR roots 定稿之前。
- 这是 release 默认分配消除的一部分，不增加新的开关或等级。接口值、父表投影、泛型实例、跨 Cone 产物、公开 ABI 与 GC 对象表示均保持；无需重建预编译 sysroot。

创建过程尚未展开、仍有多个 receiver 调用、对象逃逸、需要身份／地址、无法证明正常／异常路径安全或净成本仍过高的情况继续保留。例如只有一次遍历、iterator() 创建本身未进入内联范围时，这项优化没有可用的局部分配来源。它不等于所有 iterator 消除，也没有加入跨调用特化或部分物化。

## 正确性与生成代码

- 格式化与 workspace Clippy 通过；本机仅运行 MIR 优化模块的 47 项 Rust 测试，覆盖新调用选择／关闭字段替换的对照、callee 与 caller 的未知调用／身份／取址／外来合流、两个剩余调用，以及已有字段快照、继承、循环、递归、增长限制、box／closure、冷分支和 intrinsic。
- Darwin ARM64、Linux GNU、Linux musl 各验证两组正式专测：`local-class-scalars` 的 debug／release 行为，以及 `local-class-scalar-roots` 的 release moving／minor GC。每个目标最终三种构建变体、五个步骤通过；只在 GC 用例调整后重跑该用例，没有全量验收。
- 普通用例增加真实集合的空表和重复遍历。GC 用例用 `ArrayList<Payload>` 反复遍历，Payload 包含 class、tuple、String 和 interface 引用，复制后立即 GC；MIR 确认 `drain` 的 iterator 创建与 next 调用均已展开，`ListIterator<Payload>` 分配消失，实际覆盖了消除后的引用根和聚合副本。
- 性能程序的 `lists` 中 `ListIterator<Long>` 分配、next 调用和该对象的字段操作消失；后续去虚化将底层集合 get 变成直接调用，size 读取被展开。ArrayList 自身及错误分支对象保留。LIR poll 仍为 4 个；该函数的机器指令由 Darwin 298→241、两个 Linux 目标 301→251。
- 三目标中，Point、手写 Cursor 和无对象对照的 MIR／LIR 完全一致；完整程序的 81 条 TD／布局记录也完全一致。优化没有为字段替换保留被消除的对象根。
