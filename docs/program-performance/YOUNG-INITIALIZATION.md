# 年轻对象初始化屏障消除

2026-10-26，在 `6b76118ea` 的接口 SSA、生成分配和 TaskContext fork 基础上，复用实际 TLAB 成功事实，省去年轻目标初始化时的卡表查询和标记。**release 默认开启**，沿现有分配优化配置；debug、慢分配和未证明的写入保持原屏障。普通对象与 typed 小型 box 共用规则，无类型／函数名特判，不改变 ABI、对象体积、接口表示或诊断代码生成条件。

## 实现与边界

- 生成分配返回对象与已有 fast／slow 判断的布尔 SSA 值。成功 bump 保证对象属于 nursery，完成登记不经过 safepoint；慢路径仍可能返回其他代的对象。引用字段写入和 box payload 复制之后，仅在实际慢分支执行原单槽或完整值屏障。
- 普通字段复用尾部清零分析的未取址局部副本与重赋规则；沿无条件边向单前驱、尚未发射的块传递事实，使内联构造器的独立入口也能命中。条件分支、合流、回边、调用、poll、取址、对象读取、外传及未知操作结束证明。前驱统计包含 invoke 的正常与异常边，不增加通用数据流框架。
- 源引用仍由原根计划保活并在分配后恢复，真正的字段写入／payload 复制使用更新后的引用。年轻事实不成为 GC root，也不跨 GC 缓存。对象头、引用槽和 padding 的清零保持；collector 的晋升与 survivor 继续按实际引用建立 remembered set。
- 零引用写入不生成额外屏障分支；编译期确定不可能成功 bump 的分配保留原来的字段卡区复用。动态慢分支仍保存完整屏障代码，新增的条件与分支可能使静态函数变大。普通数组发布、原子写入、未知来源对象和 runtime C 后备仍按原协议处理。

实现位于 codegen 的 allocation、allocation_initialization、young_initialization 和 field／box 写入路径。MIR／LIR 根计划、晚期 aggregate 分解及 RS4GC 顺序不变；三目标的三个对照程序 MIR／LIR 均与基线逐字节一致。runtime ABI **18**、metadata ABI **9** 和 `.slib` 格式保持；已编译库需要重建才能获得新的生成代码。

## 必要验证

- 两机格式化、release workspace Clippy，以及各 25 项分配／装箱定向单测通过。覆盖实际 TLAB 判断、debug、局部快照／重赋、取址、观察／调用边界、单前驱与合流、多引用范围屏障、慢分配原卡区复用，以及 box 的真实 statepoint／relocate。
- 三目标各通过 context-fork、gc-writes、boxing-payload-roots 三组、六个 profile 变体，共 12 次程序运行；包含普通、moving／minor stress、构造中 GC、接口字段、聚合装箱、数组发布、原子更新、异常和协程恢复。统计补测确认 full 搬迁和 48 次 minor／15 次 full 的分配压力；另以 `SCOOP_GC_SURVIVOR=1` 运行 gc-writes，通过一轮 minor 与三轮 full。统计没有 survivor 数量字段，不把开启选项本身当作保留数量测量。
- ARM64 与 x86_64 机器码均确认：引用 box 的快分支跳过范围屏障调用；普通对象快分支直接写入两个引用字段并跳过页表／卡标记。慢分配之后先重载引用再存入对象，向外部数组发布时仍执行完整屏障。完整函数保留慢代码，不能把全函数指令条数直接当作快路径执行成本。
- 收尾只补测编译期恒慢路径，三个程序和 core／std／test／json 四库在三个目标上均与此前已验版本逐字节一致，因此复用运行与 GC 结果，并用最终工具重测编译成本。分配 IR 探针已限定为被测分配，排除共享 fixture 中另一处 box 的干扰。Linux 临时脚本与标准库重名、私有副本缺少一个 fixture 的环境问题已闭合，没有扩大为全量验收。

## 运行与分配

基线与候选使用同一源码、相同输入和各目标逐字节相同的 92 个 runtime 对象。ARM64 为 M3 Ultra／LLVM 22.1.8；x86_64 为 nuc12 i7-12700H／LLVM 22.1.2，分别运行 GNU／musl。正常 release，一对预热、五对 AB／BA，不开 GC stress／统计，不固定 CPU；下列百分比是中位数耗时变化，不是显著性或周期估算。

[装箱基准](../../tests/benchmarks/scalars/boxing.scoop)每次将对象发布到 256 项循环数组，输入 Node／String 在计时前建立。模式 2 为含两个引用的 struct box，模式 4 为相同字段的普通 class，实例均为 40 B；每轮一千万次。阶段测量包含实际分配、初始化、数组发布及相应 GC。

| 内核，ms | ARM64 Darwin | x86_64 GNU | x86_64 musl |
| --- | ---: | ---: | ---: |
| 含引用 box | 73.759→49.699（−32.62%） | 100.069→65.146（−34.90%） | 105.830→79.032（−25.32%） |
| 普通引用对象初始化 | 67.811→49.541（−26.94%） | 79.981→66.173（−17.26%） | 86.888→77.953（−10.28%） |

以上两个程序模式的整进程耗时分别降低 ARM64 30.46%／24.83%、GNU 33.64%／15.50%、musl 23.16%／9.75%。已有协程程序每轮执行两百万次，整进程结果如下：

| 协程模式 | ARM64 Darwin | x86_64 GNU | x86_64 musl |
| --- | ---: | ---: | ---: |
| tail immediate | −5.06% | −0.45% | +0.81% |
| tail deferred | −3.16% | −2.40% | −2.53% |
| synchronous leaf | −9.37% | −6.29% | −4.10% |
| synchronous wrapped | −9.41% | −5.59% | −6.48% |

ZST／Long／宽值 box 对照的整进程变化为 ARM64 −0.91%／−0.95%／−0.14%、GNU +0.98%／+1.26%／−0.89%、musl +0.62%／−1.54%／−2.35%；这三个函数的机器指令数不变。保留这些正负变化和 musl immediate 的回退，没有按函数调整布局或反复测到转好。

分配统计另行运行，并固定相同 `argv[0]`，排除可执行文件名长度带来的启动 String 差异。十万次含引用 box／class 两模式均为 **4,006,328 B、3 次 minor、0 次 full**，各目标前后相同；两百万次 tail 为 **672,000,352 B、644 次 minor、1 次 full**，同步 leaf 为 **416,000,296 B、398 次 minor、0 次 full**，前后相同。实际分配未消除；现有 JSON 没有总分配次数字段，不另造该项测量。收益来自初始化屏障及其调用／保存恢复成本的减少。

首版仅处理同块，在 ARM64 已改善含引用 box，但普通 class 因构造器处于单前驱后继而未获益（内核 +0.25%）。随后扩展必要的直线传播才获得上表 class 收益；首版逐次数据仍在仓库外保留。
