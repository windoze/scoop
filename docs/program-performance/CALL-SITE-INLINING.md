# 调用点内联评分

本项接续 [循环优先级](LOOP-INLINING.md)、[字段替换估价](ITERATOR-INLINING.md)和[按需优化报告](OPTIMIZATION-REPORT.md)，以实现规范 2.19 为准。

后续累计增长分配由[自然循环的内联增长分配](HOT-REGION-INLINING.md)接续；下面保留本项交付时的模型与测量。

现有 MIR 已按调用点代入参数、化简分支，按循环深度优先选择，并在展开后重新分析 caller；不足是最终仍用统一的执行成本上限，极小正文直接通过，循环深度不进入收益。跨 Cone 的 HIR 正文还受 96 节点过滤。LLVM 普通管线没有常规内联器，只有函数内优化及私有卡屏障 helper 的必需展开；普通内联继续在 LIR roots 生成前完成。

新策略缓存稳定 callee 的事实及独立化简结果，每个调用点重新估计收益与净增长。收益包含调用边界、可消除的值 ABI 适配、实际参数使保留路径减少的操作和已有证明支持的局部分配消除。常量条件排除的未执行块只降低体积；不将整段 callee 执行成本或未知 GC 开销当收益。静态循环深度放大收益，冷出口降低收益，净增长、复杂度及 caller 当前规模构成惩罚，累计增长与递归深度保持有界。

低成本评分随 release 默认启用；debug 保留普通调用。移除可移植 HIR 正文的尺寸过滤，各 profile 导出相同正文范围，沿用 `.slib`、实体身份、runtime 和调用 ABI。没有新增昂贵试内联或策略开关。诊断仅在显式请求时收集，不向程序或库生成诊断代码。

评分使用既有操作权重。令 `B = 6 + ABI + 保留路径化简 + 已证分配替换`，`F` 为调用点频次，接受条件为 `4 × F × B ≥ P`，同时满足累计增长和合法性限制。

- 普通 `F=1`；自然循环深度 1／2／≥3 分别为 4／16／32；只通向异常或 trap 的冷出口为 1/8。频次是静态启发式，不是实测调用次数。
- `G=max(化简后 size−6,0)`，`H=min(G,max(execution−6,0))`。`P=ceil((G+3H)/4)+2C+floor(G×caller_size/512)`；`C` 为保留条件分支数加两倍 unwind 边数。原有 execution 权重在此只用于区分冷代码的空间惩罚，不再设置执行成本门槛。冷代码仍完整计入 `G`。
- ABI 估价复用普通聚合值 3、接口 1、标量 0 的复制权重；参数计调用两侧，使用的返回值计两侧，未使用结果仅计 callee 一侧。未给 GC roots、入口 poll 或保存／重载额外记分。
- 基础累计增长上限 `min(原 caller size/2+128,384)`；`F≥4` 允许两倍，`F≥16` 允许四倍，最高 1536。同步 suspend 基础常数仍为 96。实际每次扣 `max(G,1)`，跨轮不返还；当前 caller 越大，新增代码惩罚越高。

这些参数统一适用于任何名称、库和类型。没有引入动态试内联或完整 PGO。具体结果如下。

## 实际决策与验证

- 新增 `inlining/call-sites` 用同一个跨 Cone `mix` 对照普通调用、双层循环和常量实参。普通正文估价 297、净增长 291，普通点收益 24、惩罚约 298，增长上限 134，保留调用；双层循环收益 384、惩罚 318，允许展开。常量分支后体积降至 7，只有保留路径中的 2 单位工作计作化简收益，被排除的大块正文不计运行收益。debug consumer／release provider 与反向组合均覆盖。
- 同一小函数在普通点展开、在冷异常分支保留。MIR 单测另用体积不超过 12 的函数覆盖原先的无条件小函数档；同一 caller 内的两个点得到不同结果。
- 原成员用例中，21 单位的对象工厂现可内联，`ClassAlloc` 和真实初始化调用仍保留。`Recorder.validate` 在独立小 caller 内展开，在较大的 callback caller 内因规模惩罚保留；并非按函数统一选择。
- dispatch 原先已经展开 `ListIterator.next` 和 `ArrayList.get`，但最后一层 `MutableArray<MaybeUninit<Shape>>.get` 需要增长 35、只剩 23，仍调用外部入口。新策略在双层循环的这一调用点展开，后续标量替换和清理可继续进行；未知 `Shape` 分派保持动态。Complex 的 `times`、`plus`、`norm2` 在基线和新版都已展开。
- 本机通过 70 项 MIR 优化、4 项同步 suspend、4 项普通跨 Cone 正文单测；Linux 重复前两组。三目标各通过 `call-sites`、`members`、`growth`、`semantics`、`stage-observations` 五组、9 个 variants、41 个进程步骤。覆盖实际调用消失／保留、参数顺序、窄整数及值快照、异常、移动／minor GC、跨 profile 及按需诊断。Rust 格式化和涉及 crate 的 all-targets Clippy、固定版本 Ruff 均通过；没有运行全量 fixture 或 workspace 测试。
- 新 fixture 检查 MIR 及 LIR 中实际调用；专用内核还检查机器码。内核的 `mix` 普通调用被删除，原有 safepoint 慢路径保留。`stage-observations` 验证开启报告只补充观察输出，机器产物保持不变；本项没有 runtime 诊断代码。

本轮采用低成本的摘要复用和静态调用点评分作为 release 默认策略：dispatch 在三目标均有明显收益，代表程序的代码与文件未膨胀，编译成本变化较小。评分仍是启发式，不承诺每处展开都更快；保留大正文内核无稳定加速、GNU trees 小幅退化的结果。没有引入成本较高的动态试内联或更激进等级。未来 profiling 可提供更准确的频次及类型事实，继续进入调用点模型，不改变正文可用性与语义合法性的边界。
