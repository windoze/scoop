# 调用点异常路径特化

本项推进 B1 的资源作用域抽象消除，并为 C1 提供首个按需无抛出分析消费者。相对基线 `e9668cf29`，先在调用点证明异常边不可达，再按真正剩余的正文决定内联；`Disposable.use` 的普通成功路径可以继续完成闭包与局部对象消除。

## 实际实现与开启条件

- **release 默认启用**，沿用普通 MIR 内联和原执行成本、累计增长与深度限制，没有新增公开开关或等级。debug 保留原始异常路径；所有 profile 的语言语义、GC 与产物 ABI 一致。
- 复用已有实参常量／exact receiver／closure 数据流和完整签名派发，将确有唯一实现的调用改为直接调用。没有按 `use`、类型名或方法名特殊处理。
- 标量运算、普通字段读写、捕获读取及局部操作按其实际语义判断；调用只有在本次已可用的完整正文及其正常可达依赖均无抛出时才获得证明。无正文的外部／native 调用、未知动态目标、可达递归依赖和可能失败的操作保留未知。NoGC、无写入、不捕获等信息不等同于无抛出。
- 只有块中全部操作及终结指令均不会发起异常，才删除其 unwind 边；复用普通可达性清理失去入口的处理块。最终仍有 native 异常状态、catch／resume／rethrow 的候选保持原调用，不复制或共享新的异常作用域。正常 finally／dispose、副作用、参数求值和返回快照保持；清理本身若抛出，仍进入原调用方的处理路径。
- 未变化模板的 EH 特征只检查一次，无抛出依赖按需缓存于本次候选选择；显式工作栈处理 helper 链，循环依赖保持未知。不新增持久摘要、源码导入通道、IR 格式或 runtime 接口。规范见实现规范 2.3、2.19。

普通跨 Cone 正文的导出范围保持现状：可使用已有的普通标量正文证明依赖，普通 EH／字段正文尚未全部导出时保留外部调用。core `use` 通过已有泛型实例化获得完整正文。带异常处理的调用方仍受原分配消除边界限制：即使 `use` 调用已消失，尚未消除的对象或闭包分配也如实保留。

## 必要验证

- Darwin 与 Linux 各通过 63 项 `scoop-mir-lower tests::optimization`，包含五项新增回归：无抛出与真实抛出、递归拒绝、48 层 helper 链、exact callback 特化、关闭内联，以及正常 finally 和参数／返回快照。修改后先执行 Rust fmt／workspace Clippy；Python 检查使用 Ruff 0.16.10。
- 三目标各通过 `exception-path-inlining` 专测的两个 profile、8 次正式进程调用；provider 与 consumer 使用相反 profile。覆盖已导出普通依赖、未导出 EH 正文、泛型 core use、清理异常进入调用方 catch、真实回调异常和未知函数值。
- release 专测启用 moving GC，显式检查逃逸对象经闭包返回、全局引用清空后的存活。LIR 中两次 `gcCollect` 各只有该对象一个 live root，闭包声明不变成额外根。本机独立诊断确认 13 次 full collection、504 B 实际复制。
- 三目标各通过 core consumer Cone 的三项资源测试，覆盖 receiver 单次求值、清理前的返回值快照、单一失败身份、双失败 `ResourceUseException` 身份，以及既有 suspend／GC 组合。没有全量验收，也没有重建未变化的预编译系统库。
- 基准按 1、2、3、4、7、64、65、1000000 次分别运行 use／直接写法，两版输出都与独立计算结果一致。检查实际内核 MIR、LIR 和最终机器码；release use 的闭包、Lease 分配、普通调用与异常处理均消失，原两个 poll 保留且 live 集合为空。机器指令数由 156／148／148 降到 86／90／90，与各平台直接写法相同；ARM64 两个内核仅重定位后的分支地址不同。

## 运行与空间成本

源码为 [资源作用域基准](../../tests/benchmarks/abstractions/resources/README.md)。两版使用同一源码与预编译 sysroot；本机 M3 Ultra／LLVM 22.1.8，nuc12 i7-12700H／LLVM 22.1.2，Linux 计时固定 CPU 4。每组一次预热、七对 AB／BA 独立进程，以阶段墙钟中位数比较；GC 诊断单独运行。

长样本每次执行 20000000 轮，阶段包含 Lease 创建、捕获本轮输入、读取、修改字段的 dispose 和最后读取，输出在计时之后：

| 目标 | use 基线 → 新实现 | 耗时变化 | 新实现的直接写法 |
| --- | --- | --- | --- |
| ARM64 Darwin | 400.957 → 11.156 ms | −97.22% | 11.150 ms |
| x86_64 GNU | 419.412 → 4.802 ms | −98.86% | 4.805 ms |
| x86_64 musl | 428.733 → 4.796 ms | −98.88% | 4.797 ms |

三目标的 use 分配均由 640000128 B 降为固定 104 B，minor collection 从 612 次降为零，扫描 root slots 从 22644 降为零。直接写法仍为固定 104 B，其长阶段前后变化为 −0.36%／+0.01%／+0.01%。整个进程的墙钟基线／新实现比值为 15.97／38.83／22.05；峰值 RSS 中位数在本机从约 10.63 MiB 降到 9.23 MiB，Linux 观测值保持不变。

单次短样本的阶段包含计时入口成本：use 为 2000→2000／1579→1424／867→749 ns；直接写法为 2000→2000／1522→1513／675→736 ns。保留 musl 直接对照的 +61 ns 波动，不把这些短区间百分比解释为稳定收益。

| 增量成本 | ARM64 Darwin | x86_64 GNU | x86_64 musl |
| --- | ---: | ---: | ---: |
| text | −584 B | −512 B | −576 B |
| 根 `.slib` | −29330 B | −36270 B | −36182 B |
| 完整程序 | −9232 B | −12416 B | −12416 B |
| 资源基准编译墙钟 | +0.60% | −0.94% | −0.43% |
| 引用数组对照编译墙钟 | +2.43% | +0.12% | −0.35% |

编译成本用直接 `scoopc build`、同一输入与已准备依赖，六对交错编译，首对预热不进入中位数。两组源码的编译峰值 RSS 均未增加，变化为 −0.10%～−0.96%；每版重复产物一致。引用数组对照的 `.slib` 在两版间逐字节相同，编译时间差保留，不因机器码相同而忽略分析成本。

有限范围的运行收益稳定，未增加静态空间，沿用 release 默认策略。一般 EH 内联、更多导出正文和更广效果／逃逸摘要继续分项推进。数据针对同一 Scoop 程序的编译器前后对照；综合负载与跨语言比较继续沿性能主线开展。

原始构建、测量、失败闭合日志和机器码保留在两机各自的 `tmp/program-performance/eh-inlining`，不提交原始归档。
