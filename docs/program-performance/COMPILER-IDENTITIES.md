# 编译依赖身份图的共享与增量处理

## 已采用的实现

所有编译 profile 默认使用，无新增开关、持久 ID、wire 或 ABI 版本变化。

- `ValidatedIdentityGraph` 的完整节点容器和声明顺序共享；普通 clone 不再复制两张 HashMap。继续扩展新层时按实际写入取得容器副本，已有 canonical keys 仍共享。
- 节点同时保存 typed ID 与 canonical key，消除第二张长键索引。外部图导入逐项合并，不反复排序候选、排序 keys 或重建此前全部 key 的查找集合。
- 已完成图的引用不再变化，环检查只枚举新增候选之间的边，使用无递归队列。同批已 resolve 的候选仍参与环检查；对旧节点的引用继续检查存在性与层次方向。输出排序和最小错误节点保证确定性。
- semantic session 共享已有实体索引和导入映射；同一个不可变图再次导入时复用结果，扩展图仍核对 origin 与 typed key。批量导入保持失败不部分提交。
- 进程内身份索引使用维护中的 `rustc-hash 2.1.3`；持久 ID 的 SHA-256／规范编码不变。当前 Cone 已导入 provider 的完整机器身份图时，不再先导入其 HIR 子集。

实际需要的 MIR／LIR foundation、布局、ABI 与 definition 目录仍按当前 reader 读取。此次没有减少持久元数据字节或更改能力分区；机器层读取的收益来自其中图复制、导入和验证的重复工作减少。所选 provider 的首次解码、key 解析与必要结构检查仍是后续编译热点。

## 可比较基线与验证

基线树为 `6a5a5cb34`，与 merge commit `96d56fc3c` 相同。独立保存正常 release 的前后工具，使用同一 M3 Ultra、LLVM 22.1.8、Darwin arm64、同一套预编译 core／std／math 和 runtime。mm 的旧采样与当前工具时间不一致，只用于定位问题，没有混入本轮性能数值。

hello、nbody 每次正文修改确实触发一个 compiler child；路径依赖增加公开函数的默认参数，provider 与 consumer 均重编译。无改动命中复用同一输出位置，为零 child；冷构建采用新项目 cache，系统库仍预编译且不清操作系统页缓存。每次都运行所得程序并检查结果。

首轮各七次结果显示真实正文改动重建减少约 32%／41%，公共签名改动减少约 37%。随后用五对 AB／BA 交替复测固定源码和配置，具体中位数与范围记录于下表。

Rust fmt、release workspace Clippy 通过；ARM64 与 Linux x86_64 各 34 项身份定向回归通过，包含新增自环／多节点环、16,384 节点非递归深链、共享快照扩展、冲突 key／类型、缺失与未来层引用、失败原子性及损坏 wire 的确定性。Darwin 两组正式 CLI 专测（菱形依赖缓存、core 符号跨两层产物消费）共六次进程调用通过。没有全量 fixture；Linux 独立源码环境验证身份实现，没有将 ARM64 的编译时间外推到 x86。
