## Nursery 与引用回写

同一 Scoop 程序只更换 runtime 容量常量。1／4 个 mutator 各执行 80 个分配帧，每帧生成 32768 个对象并更新旧引用数组，保留比例为 1%／50%／100%；预热后各交替运行三轮，校验对象内容与校验和。未开启 GC stress。下表耗时、计数、最大 pause 和 RSS 为三轮中位数；帧 p95 合并三轮逐帧观测，表示实际分配帧延迟，不是 GC 事件 p95。

16 MiB 在所有这些运行中均不发生 minor，也不复制对象；收益包含 collector 路径变化，不能仅归因于 refill 减少。低存活单线程的 1／4／16 MiB 累计 pause 为 21.77／5.97／10.96 ms，复制量为 0.80／0.20／0 MiB，累计 stop-wait 为 0.004／0.001／0.005 ms。高存活四线程分别复制 298.43／232.19／0 MiB、晋升 319.26／294.25／118.00 MiB，累计 pause 为 965.16／762.31／108.54 ms、stop-wait 为 10.36／2.46／0.83 ms。16 MiB 的零复制并不表示零晋升。

高存活四线程、1 MiB 下，显式选择 1／4 个 GC worker，三轮累计 update 中位数为 385.62／373.92 ms，整个已停稳阶段为 1037.06／955.35 ms；该开关改变既有 GC 工作分配，不能据此把全部差异归于回写并行化。本期不另建回写调度器。

**决定：保留 1 MiB 和既有 worker 策略。** 4 MiB 在高存活四线程出现明显 RSS 峰值，16 MiB 增加低存活短帧尾延迟和内存占用；吞吐改善不足以替换 M56 的桌面默认取舍。此程序是含旧到新引用的分配帧模型，不是 GUI 渲染器；现有统计没有逐事件完整“请求至恢复”分布，stop-wait 与已停稳 pause 分开记录，不能用两者累计值声称完整阻塞分位数。

## ABI、查表和字符串

| 候选 | 独立对照 | 本期决定 |
| --- | --- | --- |
| 24 字节 HFA | 独立 C translation units 中一亿次同算法 V3 add／scale，严格浮点；五轮 pointer／HFA 中位数 178.05／174.22 ms，结果相同。属于 ABI 调用控制实验，没有修改 Scoop ABI | 约 2.2% 的小幅控制实验收益不足以支持 ABI／跨产物合同变更；保留现状 |
| 父接口表缓存 | 直接复用当前 runtime 查找函数，比较两千万次 2／8／32 项表的末项查找和已缓存表指针；五轮中位数分别 25.49／56.02／191.44 ms，缓存约 15.1 ms | 线性成本随接口数增长，但增加父表指针影响所有相关 itable 布局；当前真实遍历负载已因 TD 重复查询消除显著改善，本期不改变布局 |
| String hash 缓存 | 复用当前 hash 算法，与独立原子 side cache 对照。20 万个 16 字节字符串仅用一次：1.06／8.48 ms；重复十次：11.04／9.82 ms。256 字节字符串仅用一次：42.67／47.02 ms；重复十次：426.90／47.83 ms | 长字符串反复使用可获益，短或单次字符串则有额外成本；保留无缓存布局 |

父接口表和 String 实验为隔离的 C 控制测量，未将结果宣称为完整 Scoop 程序收益。String side cache 使用原子 hash 与 acquire／release 的 ready 标志，当前对照为单线程，不代表并发收益；若嵌入对象还需增加字段与对齐，并改变常量字符串和生产／消费布局。本期不为该候选引入对象字段或持久 ABI。

## HashMap 槽位掩码

外置 std 副本将二次幂容量的起点计算改为掩码，极端非二次幂容量仍用原余数，修改检测与探测规则保持。同一编译器／runtime，预热后五轮交替运行：hashLong 0.6984 → 0.7025 秒，hashString 0.2433 → 0.2445 秒，结果相同。没有测出稳定收益，保留现有实现，不为假定的容量不变量改变极端分支。

Darwin 最终导出精简已采用，体积、启动及 RSS 对照见 [实施记录](PROGRESS.md)。其余已采用功能也分别记录了单项验证与测量；组合结果与验证范围见 [验收记录](ACCEPTANCE.md)。
