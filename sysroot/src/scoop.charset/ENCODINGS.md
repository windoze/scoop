# 字符集名称

M61 固定 encoding_rs 0.8.42 的遗留编码映射，配合 Rust 标准库标量转换提供真正的 ASCII、Latin-1、UTF-8／16／32。共 **43 个 canonical name**；下表显式列出所有别名，大小写无关，不去除空白、不模糊匹配、不回退 locale。

Unicode 无字节序名称仍要求 BOM 或显式字节序。ISO-8859-1 保留 C1 控制，不解释为 Windows-1252；ASCII 拒绝高位字节。不存在的历史编码不会注册为空壳。

## M54 → M61 的映射变更

- GB18030 使用 encoding_rs 的 WHATWG 2022 变体：两字节映射采用 2022 更新，A3 A0 映射 U+3000；原四字节别名保留 2005 映射。19 个 PUA 不能往返：U+E5E5 不可编码，另外 18 个（如 U+E78D）仍编码为兼容的两字节值、解码为新的非 PUA 标量。它不是严格的 2005 或 2022 全集，移除 `GB18030:2005` 和 `GB18030:2022` 名称。
- GBK 使用相同解码器，解码也接受 GB18030 四字节序列；编码限于 GBK 两字节集合及欧元单字节 80。不再声称它是严格 GBK 验证器。
- BIG5 使用 WHATWG 的 HKSCS 扩展映射，部分双字节解码为两个标量；编码的有效集合与解码不完全对称。旧 HKSCS 年份名称全部移除。
- SHIFT_JIS 使用 Windows 扩展；EUC-JP 使用网页 JIS 映射，解码支持 JIS X 0212，编码不输出该集合；ISO-2022-JP 使用网页状态机与错误恢复，不提供 JP-1／2／MS 变体。EUC-KR 使用 Windows-949 扩展。
- Windows 单字节表部分旧未定义位置成为 C1 控制；ISO-8859 的未映射位置仍按上游报错。CP1258 不隐式分解越南语音调或组合解码结果；需要 NFC 时由调用者明确执行。MACCYRILLIC 使用网页 x-mac-cyrillic 表。
- 所有映射的非双射、兼容别名与非法单元恢复采用 encoding_rs 0.8.42 的定义。严格只表示拒绝该映射中的非法序列／不可表示标量，不保证编码后逐标量往返相等。

## 明确移除的名称

以下 65 个旧 canonical name 及其原别名均不再支持；不把标准／厂商／年代名称偷偷转成近似编码：

`ARMSCII-8`, `BIG5-HKSCS`, `BIG5-HKSCS:1999`, `BIG5-HKSCS:2001`, `BIG5-HKSCS:2004`, `C99`, `CP1131`, `CP1133`, `CP850`, `CP862`, `CP932`, `CP936`, `CP949`, `CP950`, `EUC-CN`, `EUC-TW`, `GB18030:2022`, `GB_1988-80`, `GB_2312-80`, `GEORGIAN-ACADEMY`, `GEORGIAN-PS`, `HP-ROMAN8`, `HZ`, `ISO-2022-CN`, `ISO-2022-CN-EXT`, `ISO-2022-JP-1`, `ISO-2022-JP-2`, `ISO-2022-JP-MS`, `ISO-2022-KR`, `ISO-8859-11`, `ISO-8859-9`, `ISO-IR-165`, `JAVA`, `JIS_C6220-1969-RO`, `JIS_X0201`, `JIS_X0208`, `JIS_X0212`, `JOHAB`, `KOI8-RU`, `KOI8-T`, `KSC_5601`, `MACARABIC`, `MACCENTRALEUROPE`, `MACCROATIAN`, `MACGREEK`, `MACHEBREW`, `MACICELAND`, `MACROMANIA`, `MACTHAI`, `MACTURKISH`, `MACUKRAINE`, `MULELAO-1`, `NEXTSTEP`, `PT154`, `RK1048`, `TCVN`, `TIS-620`, `UCS-2`, `UCS-2BE`, `UCS-2LE`, `UCS-4`, `UCS-4BE`, `UCS-4LE`, `UTF-7`, `VISCII`.
